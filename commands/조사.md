# 조사 (Research)

claude.ai 웹의 **Research** 기능을 Claude Code 환경에서 재현하는 자립형 진입점. 단일 질문을 여러 하위 주제로 분해해 **주제별로 cold context Agent 를 병렬 spawn** 하고, 각 Agent 가 `WebSearch` + `WebFetch` 로 자율 다단계 검색을 수행한 뒤, Lead(본 세션 Claude)가 **인용(출처) 포함 종합 보고서**를 작성한다.

> **[용도 한정]** 여러 출처를 훑어 종합해야 하는 *조사·리서치* 전용 (시장 비교 / 기술 동향 / 다출처 사실 종합 / 의사결정 근거 수집). 단순 사실 1건 확인·코드 작성·코드베이스 탐색은 본 커맨드 대상이 아니다 → 직접 답변 / `php8`·`api-team` / `Explore`.
> **Why:** Research 의 가치는 (1) 하위 주제 분해로 검색 누락 방지 (2) 병렬 cold context 로 독립 검색 폭 확보 (3) 인용으로 추적 가능한 근거 제공 — 이 3 요소를 매번 즉흥 재구성하면 단발 웹 검색과 다를 바 없어진다. 본 커맨드가 분해→병렬→인용 골격을 SSOT 로 고정한다.

> **[claude.ai Research ↔ 본 커맨드 매핑]**
> | claude.ai Research | 본 커맨드 |
> |---|---|
> | lead agent 질문 분해 | Phase 0 (본 세션 Claude) |
> | subagent 병렬 자율 검색 | Phase 1 (`general-purpose` Agent N개 병렬 + WebSearch/WebFetch) |
> | 결과 종합 + 인용 보고서 | Phase 2 (Lead 종합) |
> | (앱 내 표시) | Phase 3 (`output/research/` 파일 저장 + 요약 보고) |
> | 커넥터(Gmail·Drive 등) | 미지원 — 웹 출처 한정 (Claude Code 환경 제약) |

## 인자

- `$ARGUMENTS` = (선택) 조사 주제·질문. 생략 시 직전 응답·대화 맥락에서 조사 대상을 자동 추출.

## 동작 (4-Phase)

| Phase | 동작 | 도구 | 직·병렬 |
|-------|------|------|--------|
| **0** | **(필수 선행)** `ToolSearch(query="select:WebSearch,WebFetch")` 로 스키마 로드 → 주제를 **3~7개 하위 주제(subtopic)** 로 분해 + 조사 범위·언어·기간 확정 | ToolSearch, 본체 | 직렬 |
| **1** | 하위 주제당 `general-purpose` Agent **병렬 spawn** — 각 Agent 는 cold context 에서 `WebSearch` (2~3 쿼리) → 유망 결과 `WebFetch` (1~2건 본문 추출) → **출처 URL + 핵심 요약 + 접속일자** 구조화 반환 | Agent (병렬), WebSearch, WebFetch | **병렬** |
| **2** | Lead 가 N개 Agent 결과를 교차 종합 — 상충 정보 표시 / 합의 정보 통합 / **인라인 인용 마커 `[1]`,`[2]`** 부착 / 끝에 `## 출처` 섹션 | 본체 | 직렬 |
| **3** | `output/research/{topic-slug}/{yyyy-mm-dd}-{topic-slug}-research.md` 저장 + 사용자에게 **결론 요약 + 출처 수** 보고 | Write | 직렬 |

> **Phase 0 의 ToolSearch 는 생략 불가.** `WebSearch`·`WebFetch` 는 deferred tool 이라 frontmatter `allowed-tools` 에 등재돼 있어도 스키마가 로드되지 않은 상태이며, `ToolSearch` 선행 없이 첫 호출 시 `InputValidationError` 로 실패한다. Phase 1 Agent 에게 위임할 때도 프롬프트에 "ToolSearch 로 WebSearch/WebFetch 스키마를 먼저 로드하라"를 명시한다.

## 직병렬 실행 지침

**원칙:** 본 커맨드는 **본질적 병렬** (하위 주제별 Agent 풀-병렬 spawn 고정). Phase 결절점만 직렬.

| 태스크 | 직·병렬 | 방법 |
|--------|---------|-----|
| Phase 1 (하위 주제 N개 검색) | **병렬** | 단일 응답에서 `general-purpose` Agent N개 동시 spawn (하위 주제 = 독립, race 없음) |
| Phase 0 → 1 → 2 → 3 | **직렬** | 분해 → (병렬 검색) → 종합 → 저장 (이전 단계 출력에 의존) |

`/병렬` modifier 불필요 — 본문이 이미 명시적 병렬 spawn 을 지시한다.

## 하위 주제 분해 가이드

- **3~7개** 권장. 3 미만 = 단발 검색으로 충분 (본 커맨드 비대상), 7 초과 = 주제 중복·토큰 과다.
- 분해 축 예시: 시간(과거/현재/전망) · 관점(기술/비용/생태계) · 후보(A안/B안/C안) · 단계(정의/구현/사례).
- 하위 주제는 **서로 독립** 이어야 병렬 검색 가치가 산다. 의존(앞 결과 없이 못 찾는) 주제는 1개 Agent 에 직렬로 묶는다.

## 인용 양식 (필수)

- 본문 주장 끝에 인라인 마커 `[1]`, `[2]` … 부착.
- 보고서 말미 `## 출처` 섹션에 번호순 나열:
  ```
  ## 출처
  [1] 제목 — https://example.com/page  (접속: 2026-05-27)
  [2] 제목 — https://example.com/other (접속: 2026-05-27)
  ```
- **출처 없는 단정 금지.** Agent 가 출처를 못 댄 주장은 보고서에 "(출처 미확인)" 표기 또는 제외.

## 산출물 경로

- `~/.claude/docs/{product}/output/research/{topic-slug}/{yyyy-mm-dd}-{topic-slug}-research.md`
- `{product}` = `basename $CWD` (`.claude` → `claude-harness`). CLAUDE.md §File Paths output 7 카테고리 중 `research` 정확 매칭.
- 파일·폴더명 = ISO-8601 `YYYY-MM-DD-` **prefix** (suffix `-YYYYMMDD` 금지). `output-naming-check.sh` 정합.
- 본 산출물 = 코드 변경 없는 조사 결과물 → `output/` (CLAUDE.md "tasks/ vs output/ 용도 구분"). Gate-0 직행 (output/ 면제 경로).

## 비용 안내

| 항목 | 값 |
|------|-----|
| Agent spawn | 하위 주제 수 N (보통 3~7) |
| Agent 당 도구 호출 | WebSearch 2~3 + WebFetch 1~2 |
| 응답 시간 | 분 단위 (주제 수·웹 응답 속도 비례) |
| 토큰 비용 | 단발 웹 검색 대비 N× |

단순 사실 1건 확인이면 본 커맨드 대신 직접 WebSearch 1회가 빠르고 저렴하다.

## 호출 방식

| 인자 | 동작 |
|------|------|
| `/조사 {주제}` | 명시 주제 다단계 조사 |
| `/조사` | 직전 응답·대화 맥락에서 조사 대상 자동 추출 |

### 호출 예

```
/조사 2026년 PHP 8.4 대비 8.3 성능 변화와 마이그레이션 이슈
/조사 PostgreSQL vs MySQL 8.x 대규모 OLTP 선택 기준 비교
/조사 OAuth 2.1 PKCE 도입 사례와 권고안
```

## 트리거 제외 (의도된 차단)

| 케이스 | 대체 |
|--------|------|
| 단순 사실 1건 확인 | 직접 답변 / WebSearch 1회 |
| 코드 작성·수정 | `php8` / `api-team` / `/실행` |
| 코드베이스 내부 탐색 | `Explore` Agent |
| 의견 갈림·트레이드오프 결정 | `/토론` (16 Agent 토론) |

## §3 Checkpoint 우선 적용

- 본 커맨드는 **외부 웹 검색·읽기 전용** — 외부 시스템 *변경* 없음. read-only 외부 호출이므로 §3 "외부 시스템 연동" 중 변경계 차단에 해당하지 않는다.
- 단 Agent N개 병렬 spawn = 대량 토큰 소비 → 사용자 진행 의사 확인 후 spawn (`/토론` 비용 안내와 동일 기조).
- 조사 결과의 **코드 반영**은 본 커맨드 범위 밖 — `/분석` → `/계획` → `/실행` 별도 워크플로우로 분리한다. 조사 직후 mutation 도구 호출 금지.
