오늘 날짜 기준 업무 리포트를 생성한다.

## 데이터 소스

모든 작업 산출물은 **글로벌 루트** `~/.claude/docs/{product}/tasks/` 하위에 통합 관리된다.

- 탐색 루트: `~/.claude/docs/*/tasks/`
- `{product}` 식별: 디렉토리명이 곧 product 이름 (`basename` 기반)

## product → [태그] 매핑

| product 디렉토리 | 태그 |
|---|---|
| `hongcafe_global_backend` | `[백엔드]` |
| `hongcafe_global_frontend` | `[프론트]` |
| `infra` | `[인프라]` |
| `claude-harness` | `[하니스]` |
| `hongcafe3` / `hongcafe-japan` 등 레거시 | `[레거시]` |
| 그 외 | `[{product}]` (원본 이름 그대로) |

> 매핑에 없는 신규 product 가 나오면 원본 이름 그대로 표기하고 사용자에게 매핑 등록 여부를 확인한다.

## 수행 절차

1. `~/.claude/docs/*/tasks/` 글로브로 **모든 product 디렉토리** 일괄 스캔.
2. 각 product 의 `history.md` 에서 대상 기간(오늘/주간/월간) 항목을 확인.
3. 작업 폴더 `~/.claude/docs/{product}/tasks/YYYYMMDD/` 하위 서브디렉토리를 순회. 파일명은 `{yyyy-mm-dd}-{작업명}-{type}.md` prefix 규칙(task-docs SKILL §산출물 네이밍 규칙)을 따른다:
   - `*-analyze.md` 만 존재 → **분석 중 (30%)**
   - `*-analyze.md` + `*-plan.md` → **계획 완료 (50%)**
   - `*-analyze.md` + `*-plan.md` + `*-result.md` → **완료**
   - `*-analyze.md` 또는 `*-result.md` 단독 (산출물 유연성, CLAUDE.md §4) → 해당 문서의 체크리스트 체크 비율로 진행률 추정 (체크 0% = 30%, 50~99% = 50%, 100% = 완료)
4. `YYYYMMDD/summary.md` 에서 완료/진행 중 구분 문구를 참고로 삼는다.
5. `YYYYMMDD/todo.md` 가 있으면 미완료 항목은 `(미착수)` 로 추가.
6. 진행률 판정이 서로 상충하면 `history.md` 기록을 우선.
7. **주제별 그룹화**: 여러 날짜·여러 task 디렉토리가 **같은 주제**이면 하나의 그룹으로 묶는다 (예: "Nginx 라우팅 재설계" 그룹 아래 6건의 task 서브디렉토리가 sub-item 으로 들어감).
8. **언어 평문화**: 내부 코드네임(`p2-p3-execution-plan`, `b1-logout-api-test` 등), 사내 약어(P2/P3, IDOR, EXCLUDED_PATHS, D-28 등), 영문 기술 용어는 **처음 보는 사람도 알 수 있도록 한국어로 풀어쓴다**. 작업 목적과 효과를 중심으로 기술.

## 출력 형식

### 일일 리포트 (`/report`)

간단 1줄 형식:

```
📋 업무 리포트 — YYYY.MM.DD

[글로벌]-[인프라]-EC2 PHP 설정 반영 (완료)
[글로벌]-[백엔드]-API 인증 필터 추가 (50%)
[글로벌]-[프론트]-로그인 페이지 구현 (완료)
[글로벌]-[하니스]-docs 경로 글로벌 이관 (50%)
[글로벌]-[인프라]-CloudFront + HTTPS 적용 (미착수)
```

### 주간/월간 리포트 (`/report weekly`, `/report monthly`)

주제별 그룹 + sub-item 형식 (여러 task 가 같은 흐름으로 묶인 경우):

```
📋 업무 리포트 — YYYY.MM.DD ~ YYYY.MM.DD

[글로벌]-[백엔드]-주제 그룹 제목 (평문화된 업무 묶음)
    └ 구체 작업 1 평문 설명 (MM.DD)
    └ 구체 작업 2 평문 설명 (MM.DD)
    └ 상태: 완료 / 50% (XXX 대기) / 30% (분석 단계) 등

[글로벌]-[인프라]-다음 주제 그룹
    └ ...
    └ 상태: ...
```

## 규칙

### 공통
- 각 업무는 `[글로벌]-[태그]-업무내용` 형식. `[글로벌]` 항상 앞에 붙임. 하이픈(`-`) 구분.
- 두 번째 태그로 product 태그 (위 매핑 표) 부여.
- 여러 product 에 걸친 공통 작업(CloudFront / 도메인 / 전역 인프라 등)은 가장 대표적인 태그 1개로 분류하되, 공통 성격이면 `[공통]` 사용.
- 진행률은 task 디렉토리 산출물 기준 자동 판단.
- `todo.md` 의 미완료 항목은 `(미착수)` 로 표시.
- 오늘 작업이 없는 product 는 리포트에서 제외 (과거 진행 중 건이 남아있으면 `(진행중)` 으로 별도 표시).

### 언어 평문화 (필수)
- **내부 코드네임을 그대로 쓰지 말 것**: `p2-p3-execution-plan` → `백엔드 백로그 통합 실행 계획`, `nginx-bff-loopback` → `Nginx BFF 루프백 구성`
- **사내 약어 풀어쓰기**: `P2/P3 이월 항목` → `미완료 중·저 우선순위 백로그`, `IDOR` → `타인 데이터 조회 가능성(IDOR 취약점)`
- **영문 기술 용어 한국어 병기**: `Checkpoint` → `승인 지점`, `rewrite` → `URL 재작성`, `keepalive` → `연결 유지`, `camelCase 정규화` → `응답 필드명을 camelCase 로 정규화`
- **목적·효과 중심 기술**: 파일명·함수명 그대로가 아니라 "무엇을 바꿔서 어떤 효과를 얻었는지"
- 처음 보는 사람이 읽어도 이해 가능한지 자문 후 출력

### 주제 그룹화 (주간·월간)
- 같은 주제·같은 흐름 task 는 하나의 그룹으로 묶음. 예:
  - `nginx-*` 다수 → `Nginx 라우팅 재설계 + prd/로컬 싱크`
  - `api-test-*` + `phpunit-*` + `b1-logout-*` → `phpunit 테스트 인프라 안정화`
- 그룹 제목은 평문화 규칙 적용.
- sub-item (`└`) 은 실제 task 디렉토리 기반이되, 내부 이름은 평문 설명으로 교체.
- `└ 상태:` 한 줄로 그룹 전체 완료/진행률 요약.

### 출력 간결성
- 일일 리포트: 한 줄에 하나의 업무, 그룹화 불필요.
- 주간·월간 리포트: 주제 그룹화 + sub-item + 상태 라인.

## 주간/월간 확장

- 주간: `~/.claude/docs/*/tasks/YYYYMMDD/` 를 최근 7일 범위로 확장 스캔.
- 월간: 최근 30일 범위. 각 날짜의 `summary.md` 타이틀만 수집해도 충분.
- 인자 예시:
  - `/report` — 오늘
  - `/report weekly` — 이번 주 월~오늘
  - `/report monthly` — 이번 달 1일~오늘

## 예시 (참고용 — 주간 형식)

```
📋 업무 리포트 — 2026.04.20 ~ 2026.04.23

[글로벌]-[백엔드]-SNS 로그인·가입 단일 EP 통합
    └ 프론트엔드 계약 설계 (04.20) + 단일 EP v2 통합 (04.22)
    └ 에러 응답 필드명 camelCase 정규화 (04.22)
    └ 상태: 완료

[글로벌]-[백엔드]-백엔드 백로그 정리 + 공개 API 보안 감사
    └ 미완료 중·저 우선순위 15건 통합 실행 계획 수립 — Feature 테스트 MySQL 컨테이너 추가, Apple OAuth 실 값 배포, Google 로그인 DB 마이그레이션, 주석·코드 품질 개선 등 (04.23)
    └ 로그인 없이 접근 가능한 공개 API 경로에서 타인 데이터 조회 가능성(IDOR 취약점) 감사 — AuthFilter 우회 경로 점검 (04.23)
    └ 상태: 실행 계획 50% (승인·실행 대기) / 보안 감사 30% (분석 단계)

[글로벌]-[인프라]-Nginx GeoIP2 국가별 3-way 리다이렉트 prd 배포
    └ 설계 분석: 엣지 케이스 13종 / 대체 방안 4종 (04.23)
    └ 배포: ngx_http_geoip2_module 소스 빌드 + MaxMind GeoLite2 Country DB + 주간 자동갱신 툴 설치 (04.23)
    └ 3-way 동작: 일본 IP→hongcafe.jp / 한국 IP→www.hongcafe.com / 사무실·미국·기타 → prd.gl 유지 (04.23)
    └ 운영 가이드 문서화 — 재빌드 절차 + 트러블슈팅 6건 + 롤백 (04.23)
    └ 상태: prd 배포 완료 / 실 VPN·OAuth 로그인 E2E 검증 대기
```
