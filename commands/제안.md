# 제안 (Decision Recommendation)

사용자 결정이 필요한 항목에 대해 **Claude 가 권고안을 표준 양식으로 즉시 제시**하는 가벼운 진입점. backlog·작업·분석 결과가 "사용자 결정 영역"에 걸려 대기만 할 때, 선택지·트레이드오프·추천(근거)·§3 매칭 여부를 구조화해 결정을 돕는다.

> **[용도 한정]** 결정 권고 전용 — 선택지가 있는 결정에 *단일 Claude 권고*. **Agent spawn 0 · 즉시 · 저비용.** 코드 작성·웹 조사·다관점 토론은 비대상.
> **Why:** 결정 항목이 backlog·작업에 쌓여 "대기"만 하면 진척이 멈춘다. CLAUDE.md §4.4 "장기 관점 추천" 룰(권고 시 기본옵션 + 트레이드오프 1줄 + 비기본 옵션 조건)을 **명시 진입점 + 표준 양식**으로 고정해 빈틈(적극 권고 부재)을 메운다. always-on 룰의 진입점화이지 별 SSOT 신설이 아니다 — 권고 양식 본 룰 = §4.4.

## /토론 과의 경계 (필수)

| | `/제안` | `/토론` (debate) |
|---|--------|-----------------|
| 비용 | Agent 0, 즉시 | 16 Agent 풀-병렬, 4× |
| 성격 | 단일 Claude 권고 | 다관점 독립 spawn 후 합의 |
| 적합 | 선택지 명확한 결정 (2~4지선다), 트레이드오프 단순 | 의견 갈림·아키텍처 결정·트레이드오프 깊음 |

**에스컬레이션 (필수):** `/제안` 진행 중 (a) 선택지 간 우열이 관점에 따라 뒤집히거나 (b) 4지선다+ 복잡도이거나 (c) §3 매우 광범위(헌법/아키텍처) 결정이면 → **"`/토론` 권장" 1줄 안내** 후 단일 권고(★)는 보류한다. `/제안`이 `/토론`을 대체하지 않는다 — 경계를 흐리면 중복이 된다.

## 인자

- `{결정주제|backlog-slug}` = (선택) 결정 대상.
  - **backlog slug 매칭 시** → `~/.claude/projects/*/memory/backlog_{slug}.md` 읽어 "사용자 결정 영역" / "## 사용자 결정 영역" 섹션 추출.
  - **일반 주제** → 직전 맥락 + 필요 시 코드/문서 read 로 결정 지점 도출.
- 생략 (`/제안`) = 직전 응답·대화에서 결정 항목 자동 추출.

## 동작 (단일 Claude 권고, spawn 0)

| 단계 | 동작 | 도구 |
|------|------|------|
| ① 결정 항목 식별 | backlog slug → 파일 read + 결정 영역 섹션 추출 / 주제 → 맥락에서 결정 지점 도출. **현재 코드·문서 상태 1차 확인** (backlog 메모리는 point-in-time — staleness 회피 위해 실제 현황 재확인) | Read, Glob, Grep |
| ② 선택지 분해 | 각 결정을 2~4 선택지로 분해. 선택지별 장점·단점·전제 명시 | 본체 |
| ③ 권고 구조화 | 선택지 표 + 추천★ + **근거(왜 이 추천인가)** + §3 매칭 여부 | 본체 |
| ④ 인라인 제시 | 복수 결정은 묶음 제시. `/토론` 에스컬레이션 해당 시 안내. **코드 반영은 별도 워크플로우 안내** | 본체 |

## 권고 양식 (필수)

각 결정마다:

```
## 결정 N: {결정 제목}
| 선택지 | 장점 | 단점 | 추천 |
|--------|------|------|:--:|
| A | ... | ... | ★ |
| B | ... | ... | |
근거: {왜 A 추천인가 — 현재 상태·전제·장기 관점}
§3: {매칭 여부 — 매칭 시 "사용자 명시 승인 영역"}
```

- **추천★ 필수** — 권고 없는 선택지 나열은 `/제안` 가치 0. 단 우열이 관점 따라 뒤집히면 ★ 보류 + `/토론` 안내.
- **근거 필수** — "통상" / "일반적으로" 모호 표현 금지. 현재 상태·전제·장기 관점(§4.4) 명시.
- **§3 매칭 표기 필수** — 결정 실행이 비가역·광범위·외부 시스템이면 명시. `/제안`은 권고만, 실행 승인은 별도.

## §3 Checkpoint 우선 적용

- `/제안` = **read-only 권고**. 결정 항목 파악(Read/Glob/Grep)만 수행, mutation 0.
- 권고된 결정의 **코드·문서 반영은 본 커맨드 범위 밖** — `/계획` → `/실행` 별도 워크플로우 + 사용자 승인. `/제안` 직후 mutation 도구 호출 금지 (`/조사` 패턴 동일).
- §3 매칭 결정은 권고에 "사용자 명시 승인 영역" 명시 — `/제안`이 §3 우회 통로로 작동하지 않는다.

## 산출물

- **인라인 기본** (가벼움 유지) — 결정 권고는 응답 본문에 직접 제시, 파일 미생성.
- 결정 다수·공유 필요 시에만 → `output/report/{주제}/{yyyy-mm-dd}-{주제}-proposal.md` (7메타 + 필수 12섹션, `output-report-share-guard.sh` 강제) 별도 안내. `/제안` 자체는 인라인 유지.
