# `/병렬` Modifier Slash

`/병렬 /{인자 슬래시} {인자}` 패턴 — Claude 본체가 prompt 본문 `/병렬` 키워드를 보고 **본 응답 내** Task 도구 호출을 multi tool_use 동시 spawn 으로 묶는다. marker / hook 없음.

## 진입 효과

1. Claude 본체가 prompt 본문 `/병렬` 키워드 인식
2. 인자 슬래시 본문 처리 중 Agent spawn 호출 시 multi tool_use 블록에 동시 spawn 으로 묶음
3. **본 응답 1회만 효과** — 다음 응답부터 직렬 default 복귀

## 직병렬 실행 지침

**원칙:** 본 슬래시 자체가 직병렬 modifier — 인자 슬래시의 독립 태스크를 단일 응답 내 multi tool_use 동시 spawn 으로 강제 병렬화한다. 의존성 판단·race 가드는 §활용 예 / §안전 가드 참조.

| 태스크 | 직렬·병렬 | 방법 |
|--------|----------|-----|
| 인자 슬래시의 독립 Agent spawn | **병렬 (강제)** | multi tool_use 블록 동시 spawn (본 응답 1회) |
| 동일 파일 mutation / 순서 의존 시퀀스 | **직렬 fallback** | §안전 가드 — race 시 자동 직렬 |

## 활용 예

| 입력 | 효과 |
|------|------|
| `/병렬 /자동진행 module A B C audit` | 자동진행 안에서 A/B/C 모듈 audit Agent 3개 동시 spawn (본 응답 1회) |
| `/병렬 /실행 모듈 X Y 구현` | 실행 단계에서 X/Y 모듈 동시 spawn (race 책임 = 사용자) |
| `/병렬 /분석 commerce auth member` | 분석 단계 3 모듈 동시 spawn |
| `/병렬 /api-team add` | **무의미** — 이미 병렬 default |

## 안전 가드 (자동 직렬 fallback)

| 조건 | 동작 |
|------|------|
| mutation 작업 (Edit/Write/MultiEdit) 동일 파일 감지 | Claude 본체 stderr 경고 + 직렬 fallback |
| 순서 의존 슬래시 시퀀스 (계획→실행→검증) | 병렬 X, 직렬 fallback |
| §3 Checkpoint 5조건 매칭 | 병렬 X, 사용자 명시 승인 우선 |

## 한계

| 항목 | 한계 |
|------|------|
| 60분 활성 marker 폐기 (2026-05-18) | 매 응답마다 `/병렬` 다시 입력 필요. 이전 marker 시스템보다 명시 비용 ↑ 단 SSOT 단순화 + hook 의존 0 = 장기 관점 정합 (CLAUDE.md §4.4) |
| race condition 책임 | 동일 파일 mutation 병렬 = race. modifier 사용자가 안전성 판단 |
| 중첩 (`/병렬 /병렬 /A`) | 무의미, 단일 효과 |

## §3 Checkpoint 우선 적용

본 슬래시는 §3 우회 통로 아님. mutation 작업 병렬 시 §3 5조건 매칭 그대로 적용.

## SSOT

| SSOT | 역할 |
|------|------|
| `commands/병렬.md` (본 파일) | 본문 정책 + 활용 예 (Claude 본체가 prompt 자체 해석) |
| `CLAUDE.md §4.4 자동 위임 정책` | 우선순위 매트릭스 — §3 우회 불가 |

## 호출 예

```
[사용자] /병렬 /자동진행 commerce auth member 3 모듈 분석
   ↓
[Claude] prompt 본문 `/병렬` 인식 → Agent 3개 multi tool_use 동시 spawn (본 응답 내)
   ↓
[다음 응답] /병렬 다시 입력 안 하면 직렬 default 복귀
```
