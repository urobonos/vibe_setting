# `/병렬` Modifier Slash

`/병렬 /{인자 슬래시} {인자}` 패턴 — `/병렬` 만 슬래시로 인식, 인자 슬래시 본문 진행 중 Agent 호출을 "직렬 default → 강제 병렬" 로 변환한다.

## 진입 효과

본 슬래시 호출 시:
1. UserPromptSubmit hook (`parallel-mode-marker.sh`) 가 prompt 본문 `/병렬` 키워드 매칭 → `/tmp/claude_parallel_${SESSION_ID}` marker 생성 (mtime 60분 만료).
2. PreToolUse Task matcher hook (`parallel-reminder.sh`) 가 Agent spawn 시도마다 marker 존재 확인 → 존재 시 reminder 주입 ("병렬 spawn 강제 모드").
3. Claude 본체는 reminder 본 후 multi tool_use 블록에 Task 도구 호출을 동시 spawn 으로 묶는다.

## 활용 예

| 입력 | 효과 |
|------|------|
| `/병렬 /자동진행 module A B C audit` | 자동진행 안에서 A/B/C 모듈 audit Agent 3개 동시 spawn |
| `/병렬 /실행 모듈 X Y 구현` | 실행 단계에서 X/Y 모듈 동시 spawn (race 책임 = 사용자) |
| `/병렬 /분석 commerce auth member` | 분석 단계 3 모듈 동시 분석 Agent spawn |
| `/병렬 /api-team add` | **무의미** — 이미 병렬 default, marker 효과 0 |

## 안전 가드 (자동 비활성 조건)

| 조건 | 동작 |
|------|------|
| mutation 작업 (Edit/Write/MultiEdit) 동일 파일 감지 | Claude 본체 stderr 경고 + 직렬 fallback |
| 순서 의존 슬래시 시퀀스 (계획→실행→검증) | 병렬 X, 직렬 fallback |
| §3 Checkpoint 5조건 매칭 작업 | 병렬 X, 사용자 명시 승인 우선 |
| 60분 mtime 만료 또는 `/병렬비활성` 명시 | marker 자동 제거 |

## 한계

| 항목 | 한계 |
|------|------|
| Skill tool 호출 시 hook 미트리거 | 본체가 `/자동진행` 본문을 Skill tool 로 호출 시 marker 효과 0 — 본체가 본문 직접 해석 시에만 작동 |
| race condition 책임 | 동일 파일 mutation 병렬 = race. modifier 사용자가 안전성 판단 |
| 중첩 (`/병렬 /병렬 /A`) 미지원 | marker 1회 생성, 중첩 효과 없음 |

## 중단

작업 중 사용자가 "중단" / "보류" / "멈춰" 입력 → `gate-approve.sh` 가 stop marker 생성 (auto-iterate-stop-guard 통과). `/병렬비활성` 명시 입력 시 parallel marker 즉시 제거.

## 호출 예

```
/병렬 /자동진행 commerce auth member 3 모듈 분석
   ↓
[Claude] marker 생성 → 본체가 /자동진행 본문 read → Agent 3개 multi tool_use 동시 spawn
```

```
/병렬 /실행 X Y Z 모듈 구현
   ↓
[Claude] marker 생성 → Worker Agent 3개 동시 spawn (단 동일 파일 mutation 시 직렬 fallback)
```
