# 드리프트검증 (Document Drift Verification)

새 문서를 생성하거나 직전 문서를 기준으로 작업을 이어가기 **직전**, 이번 작업의 **불변 원본(SSOT)** 대비 파생 문서에 드리프트(원본에 없던 가정·제약·해석 혼입, 의도치 않은 변형)가 끼었는지를 6단계로 검증하는 자립형 진입점. **read-only 진단** — 검증만 하고 새 문서를 만들거나 고치지 않는다. 통과(`[DRIFT-OK]`) 시에만 후속 문서 생성·이어가기를 진행하고, 문제(`[DRIFT-WARN]`) 발견 시 사용자 확인 전까지 진행을 보류한다.

> **[용도 한정]** *파생 문서가 원본에서 벗어났는지* 확인하는 검증 전용. 새 working/ 문서 생성, `/계획` step 분해, `/작업분석` 메타분석 문서 생성, 직전 산출물 기준 후속 작업 등 **"이전 문서를 토대로 다음 문서를 쓰기 직전"** 의 게이트다. 단일 작업 분석은 `/분석`, e2e 동작 검증은 `/검증`, API 명세 정합은 `/api-spec-audit` 가 담당한다 — 본 커맨드는 **문서 ↔ 원본 SSOT 정합** 한 축만 본다.
> **Why:** 모델은 직전에 자기가 생성한 파생 문서를 무의식적으로 새 SSOT로 삼고, 매 세대마다 원본에 없던 가정을 조금씩 얹는다(드리프트). 한 번에 한 줄씩이라 눈에 안 띄지만 N세대 누적되면 원본 요구사항과 결과가 조용히 어긋난다. 본 커맨드가 **원본 재고정 → load-bearing 제약 생존 확인 → 변경량 diff** 를 강제해, 파생의 파생이 권위를 갖는 사고를 차단한다.

## 인자

- `$ARGUMENTS` = (선택) 검증 대상 (파생) 문서 또는 작업명.
  - **생략** = 진행 중 working/ 문서 + 직전 생성·수정 문서를 자동 식별해 검증 대상으로 삼는다.
  - **`{작업명}`** = 해당 작업의 직전 산출물을 대상으로 삼는다.
  - **`{파일경로}`** = 명시한 파생 문서를 대상으로 삼는다.
- **원본(SSOT)은 인자로 받지 않는다** — Step 1 에서 식별하며, 불분명하면 추측하지 않고 사용자에게 확인한다(아래 Step 1).

## 동작 (6-Step) — 사용자 원본 프로토콜 1:1 보존

| Step | 동작 | 산출 | 차단 |
|------|------|------|------|
| **1. 기준 확정** | 이번 작업의 **불변 원본(SSOT)** 식별 — 사람이 직접 작성한 최초 요구사항/스펙. 모델 생성 파생 문서는 절대 기준 삼지 않음 | 원본 1건 확정 | 원본/파생 불분명 시 **추측 금지 → 사용자 확인** |
| **2. load-bearing 제약 도출** | 원본에서 "어기면 결과가 틀어지는" 제약을 추출·목록화 (인터페이스 계약 / 명명 규칙 / 데이터 형식 / 금지 사항 / 불변 조건) | 제약 기준선 M건 | — |
| **3. 원본 대조** | 직전 생성 문서 ↔ 원본 대조 → 원본에 없던 가정·제약·해석 혼입 여부 점검. 각 항목 분류: **원본 근거 있음 / 추론으로 추가됨 / 원본과 충돌** | 항목별 3분류 | **충돌 ≥ 1건 → 새 문서 생성 멈추고 먼저 보고** |
| **4. 변경량 검증 (diff 우선)** | 새 문서는 직전 문서 전체 재작성 금지, **의도한 변경만** 반영. 생성 후 직전 버전 대비 diff 제시 + 각 변경을 **의도됨 / 무의식적 변형(드리프트)** 한 줄씩 표기 | 변경 N건 + 의도/드리프트 라벨 | 드리프트 변경 발견 시 경고 |
| **5. 제약 생존 확인** | Step 2 제약이 새 문서에 그대로 살아있는지 명시 체크 | 제약 M건 생존/누락 표 | **누락·약화 ≥ 1건 → 경고** |
| **6. 컨텍스트 정리** | 새 문서 확정 시 구버전은 더 이상 권위 없음 선언 + 이후 참조에서 배제. 여러 버전을 동시에 권위 있는 것처럼 다루지 않음 | 권위 SSOT 1건 고정 | — |

> **read-only 게이트:** Step 1~6 는 모두 **검증·대조·diff 표기**다. 본 커맨드는 새 문서를 *만들지 않는다* — Step 4 의 "생성 후 diff" 는 후속 문서 생성 커맨드(`task-docs` / `/계획` / `/실행` / `/작업분석`)가 문서를 만든 *뒤* 그 결과를 본 프로토콜로 점검하는 흐름이다. 본 커맨드 단독 호출 = 생성 직전 Step 1~3·5 선검증, 생성 직후 재호출 = Step 4 diff 확정.

## Step 1 — 기준 확정 (원본 SSOT 식별)

- **원본 = 사람이 직접 작성한 최초 요구사항/스펙.** 후보: `~/.claude/docs/참조문서/*` (사용자 제공 기획안·권고안·번역본), 프로젝트 `specs/` IEEE 산출물(SRS/SDD/IDD — 사람 승인분), 사용자가 이 세션에서 직접 준 지시 텍스트, 원본 이슈/티켓.
- **파생 = 모델이 생성한 문서.** working/ 통합 문서, output/ 분석·리포트, 모델이 쓴 plan/result, 직전 응답에서 모델이 만든 요약 — 이들은 **절대 기준이 될 수 없다**.
- **불분명 시 추측 금지.** 어느 것이 원본이고 어느 것이 파생인지 불명확하면 **즉시 사용자에게 확인**하고, 확인 전까지 Step 2 로 진행하지 않는다.

```bash
# 참조문서(사람 원본) 후보 스캔
ls -la ~/.claude/docs/참조문서/ 2>/dev/null
# 진행 중 working/ 문서(파생) 식별 — 인자 없을 때 검증 대상 후보
ls -t ~/.claude/docs/working/*/*.md 2>/dev/null | head -5
```

## Step 2 — load-bearing 제약 도출

원본에서 "어기면 결과가 틀어지는" 제약만 추린다. 장식적 서술·예시·배경설명은 제외하고, **불변식만** 목록화한다.

| 제약 유형 | 예 |
|-----------|-----|
| 인터페이스 계약 | 함수 시그니처, API 요청/응답 키, 반환 타입 |
| 명명 규칙 | 식별자 형식, 파일·폴더 명명 컨벤션 |
| 데이터 형식 | 인코딩, 날짜 표기, 키 케이스(camel/snake) |
| 금지 사항 | "~하지 말 것", 사용 금지 패턴 |
| 불변 조건 | 항상 참이어야 하는 전제, 순서 제약, 범위 한정 |

> 이 목록이 **이번 검증의 기준선**이다. Step 3·5 는 이 목록을 고정 기준으로 사용한다 — 검증 도중 기준선을 바꾸지 않는다(기준 드리프트 자체 차단).

## Step 3 — 원본 대조

직전 생성 (파생) 문서의 모든 주장·제약·가정을 원본과 대조해 분류한다.

| 항목 | 분류 | 조치 |
|------|------|------|
| 원본에 명시됨 | **원본 근거 있음** | 통과 |
| 원본에 없지만 모델이 합리적 추론으로 추가 | **추론으로 추가됨** | 표기 후 유지 가능(추론임을 명시) |
| 원본 제약과 어긋남 | **원본과 충돌** | **즉시 차단 — 새 문서 생성 멈추고 보고** |

> **충돌이 하나라도 있으면** Step 4 로 진행하지 않고 `[DRIFT-WARN]` + 충돌 항목 + 권장 조치를 보고한 뒤 **사용자 확인을 대기**한다. "추론으로 추가됨" 은 차단이 아니지만, 그 추론이 사실상 새 제약을 만들고 있지 않은지 Step 5 에서 다시 본다.

## Step 4 — 변경량 검증 (diff 우선)

- **전체 재작성 금지.** 새 문서는 직전 문서를 통째로 다시 쓰지 말고 **의도한 변경만** 얹는다. 전면 재작성은 드리프트의 온상이다(보존돼야 할 문장이 조용히 바뀐다).
- 새 문서 생성 후 직전 버전 대비 **diff 를 제시**하고, 각 변경 줄을 한 줄씩 라벨링한다.

```bash
# 직전 버전이 git 추적/백업본으로 존재하면 diff
diff -u {직전버전} {새버전} 2>/dev/null
# 또는 git 추적 문서면
git -C "$(pwd)" diff -- {파일경로} 2>/dev/null
```

| 변경 | 라벨 | 판정 |
|------|------|------|
| 의도한 변경 (이번 작업 목표) | **의도됨** | OK |
| 목표와 무관한 표현·제약·구조 변화 | **무의식적 변형(드리프트)** | 경고 — 원복 또는 명시적 사유 |

## Step 5 — 제약 생존 확인

Step 2 에서 고정한 제약 목록이 새 문서에 **그대로 살아있는지** 1건씩 명시 체크한다.

| # | 제약 (Step 2) | 새 문서 생존 | 비고 |
|---|---------------|:-----------:|------|
| 1 | {제약} | ✅ 유지 / ⚠️ 약화 / ❌ 누락 | {위치 또는 누락 사유} |

> **약화·누락이 하나라도 있으면 경고.** "약화" = 제약은 남았으나 표현이 느슨해져 강제력이 떨어진 경우(예: "반드시" → "가급적"). 약화도 드리프트로 취급해 보고한다.

## Step 6 — 컨텍스트 정리

- 새 문서가 확정되면 **구버전은 더 이상 권위가 없음을 선언**하고, 이후 참조에서 배제한다.
- 여러 버전을 동시에 권위 있는 것처럼 다루지 않는다 — **권위 SSOT 는 항상 1건**. (working/ → tasks/ 이동, 구 산출물 archive 카테고리 이동 등 기존 생명주기와 정합.)

## 출력 형식 (필수)

검증 종료 시 응답에 다음 중 하나를 명시 출력한다.

- **통과:** `[DRIFT-OK] 원본 대조 통과 / 변경 N건 모두 의도됨 / 제약 M건 유지`
- **문제:** `[DRIFT-WARN]` + 어긋난 항목(충돌/드리프트/제약 누락) + 권장 조치. **사용자 확인 전까지 진행 보류.**

> `[DRIFT-WARN]` 은 Step 3 충돌 / Step 4 무의식적 변형 / Step 5 제약 약화·누락 중 **하나라도** 발생 시 부착한다. 통과 조건은 세 검증이 모두 깨끗할 때만이다.

## 워크플로우 결합 (발동 시점)

| 발동 시점 | 원본(SSOT) | 파생(검증 대상) |
|-----------|-----------|----------------|
| `task-docs` working/ 문서 신규 생성 직전 | 사용자 지시 텍스트 / `참조문서/` | 생성하려는 working/ 문서 |
| `/계획` step 분해 직전 | working/ §분석 + 원본 요구사항 | 분해하려는 step 파일들 |
| `/실행` 직전 | working/ §계획 (사람 승인분) | 구현이 따를 계획 |
| `/작업분석` 메타분석 생성 직전 | 각 작업의 원본 요구사항 | 메타분석 문서 |
| 직전 산출물 기준 후속 작업 이어가기 직전 | 그 작업의 최초 스펙 | 직전 모델 산출물 |

> 본 커맨드는 위 커맨드들의 **선행 게이트**로 끼워 호출하는 것을 권장한다 — "이전 문서 토대로 다음 문서 쓰기" 가 일어나는 모든 길목.

## 직병렬 실행 지침

**원칙:** Step 1 → 2 → 3 → 4 → 5 → 6 은 **직렬**(이전 Step 출력에 의존 — 특히 Step 2 제약 목록이 Step 3·5 의 입력). 단 검증 대상 파생 문서가 여러 건이면 **문서별 대조를 병렬화** 가능.

| 태스크 | 직·병렬 | 방법 |
|--------|---------|-----|
| 파생 문서 N건 각각 원본 대조 (Step 3) | **조건부 병렬** | 문서 ≥ 3 시 문서별 `Explore` Agent 동시 spawn (각 문서 독립 대조). `/병렬 /드리프트검증` |
| Step 1 → 2 → 3 → 4 → 5 → 6 | **직렬 필수** | 기준확정 → 제약도출 → 대조 → diff → 제약생존 → 정리 |

## 호출 방식

| 인자 | 동작 |
|------|------|
| `/드리프트검증` | 진행 중 working/ 문서 + 직전 생성 문서 자동 식별 후 검증 |
| `/드리프트검증 {작업명}` | 해당 작업의 직전 산출물 ↔ 원본 검증 |
| `/드리프트검증 {파일경로}` | 명시 파생 문서 ↔ 원본 검증 |

```

```

## §3 Checkpoint 우선 적용

- 본 커맨드는 **read-only 검증 도구** — 문서·코드 mutation 0 (`allowed-tools` 에 Write/Edit 부재). §3 비가역·외부 시스템 변경에 해당하지 않는다.
- **audit 결과 자동 수정 금지(CLAUDE.md §4.2) 정합:** `[DRIFT-WARN]` 에 자동 "수정 계획" 을 덧붙이지 않는다 — 충돌·드리프트·제약 누락 *현황만* 보고하고, 실제 수정은 사용자 명시 요청 후 `/계획`→`/실행` 별도 워크플로우로 분리한다.
- `[DRIFT-WARN]` 발생 = **사용자 확인 전까지 후속 문서 생성·이어가기 보류** (본 프로토콜의 핵심 차단). 자동 위임(`/자동진행`) 중이어도 WARN 은 사용자 결정 영역 sentinel(`[AUTO-ITERATE-USER-DECISION]`)로 종료한다.
