## ISO 주차 계산 (필수)

PowerShell 5.1 `-UFormat %V` 는 ISO 8601 부정확 → `GregorianCalendar` FirstFourDayWeek 보정 사용:

```powershell
function Get-IsoWeek($date) {
  $d = [datetime]$date
  $day = [System.Globalization.CultureInfo]::InvariantCulture.Calendar.GetDayOfWeek($d)
  if ($day -ge [DayOfWeek]::Monday -and $day -le [DayOfWeek]::Wednesday) { $d = $d.AddDays(3) }
  elseif ($day -eq [DayOfWeek]::Sunday) { $d = $d.AddDays(-3) } else { $d = $d.AddDays(4 - [int]$day) }
  [System.Globalization.CultureInfo]::InvariantCulture.Calendar.GetWeekOfYear($d, [System.Globalization.CalendarWeekRule]::FirstFourDayWeek, [DayOfWeek]::Monday)
}
```

- 열 헤더 형식 = `W{nn}(MM-DD)` (예: `W25(06-15)`). `MM-DD` = 실측 실행일.
- **같은 ISO 주차 재실행** = 레이어1 해당 주차 열을 **갱신**(새 열 추가 아님) + 레이어2 해당 주차 행 갱신.
- **다른 주차** = 레이어1 **새 열 append** + 레이어2 새 주차 delta 행 append.

## 모듈 Agent 반환 양식 (Phase 1)

각 모듈 Agent 에 전달: (a) `jypark-gant.md` 해당 모듈 WBS 항목 목록, (b) be 레포 경로 + production HEAD, (c) "코드 실측만, 수정 금지", (d) 아래 양식.

```
MODULE: MOD-XX
| WBS ID | 판정 | 근거(파일:줄 또는 미구현 사유) |
|--------|------|------------------------------|
| MOD-XX-001 | ✅|🟡|❌ | app/Modules/.../Foo.php:88 / 미구현 |
SUMMARY: 완료 N · 부분 M · 미완 K (= 모듈 항목 수)
```

> 판정 기준: ✅=완전 구현·동작 / 🟡=부분 구현(스텁·일부 누락) / ❌=미착수. 기존 `jypark-gant-progress-verification.md` baseline(W25) 판정 방법론과 동일 — drift 시 baseline 우선 대조.

## 갱신 로직 (Phase 2)

0. **Agent 결과 재집계 (필수 — dry-run 발견 반영):** Agent 의 `SUMMARY`·`CHANGED-FROM-BASELINE` 자가보고는 **신뢰하지 않는다**. (2026-06-16 dry-run 에서 SUMMARY 오집계[MOD-10: 표 4/3/6 vs SUMMARY 5/3/5]·CHANGED 목록 누락[MOD-02-006·009 판정표엔 변경인데 목록 빠짐] 확인.) Lead 는 각 Agent **판정표**(`| WBS ID | 판정 |` 행)를 **전수 파싱**해 ✅/🟡/❌ 를 직접 카운트하고, baseline 현재진행률상세와 **항목별 전수 대조**로 변경분을 도출한다. 갱신 후 PowerShell 재집계(아래 §"합계 무결성")로 **레이어1 ↔ 현재진행률상세 일치를 반드시 검증** (불일치 시 상세를 진실로 삼아 레이어1 재집계).
1. **레이어1** — 각 모듈 % = `(✅수×100 + 🟡수×50) / 항목수`, 1자리 반올림. 전체 % = `(Σ✅×100 + Σ🟡×50)/183`. 이번 주차 열에 13행(12모듈+전체) 기입.
2. **레이어2** — 전주 열과 비교해 % 변동 모듈의 **개별 WBS 항목** 중 판정 바뀐 것만 행 추가 (`이전→현재`, HEAD). baseline 대비 전체 변동도 1행 요약.
3. **현재 진행률 상세** — 183행 진행률 값 in-place 갱신 (판정 바뀐 항목만 Edit).
4. **작성정보** — `기준` 행 HEAD·날짜 갱신, `전체 진행률` 행 갱신.

> 합계 무결성: 갱신 후 `✅+🟡+❌ = 183` + 레이어1 전체% = 현재 상세 재집계% 일치 검증 (불일치 시 경고).

## 경량 모드 — 폐기·완료 마킹 / 미완 출력 (bin 스크립트)

`~/.claude/bin/gantt-progress.py` — 재실측(cold Agent) 없이 개별 WBS 항목을 결정론적으로 마킹/조회. 12모듈 실측이 불필요한 3가지 정형 작업 전용. **데이터소스 = 상세표(SSOT)**, 목적 = 개별 마킹·조회 (주기 실측과 분리).

| 서브커맨드 | 처리 |
|-----------|------|
| `retire MOD-NN-NNN[,…] "사유"` | 상세표 진행률→100% · 상태→`⛔ 폐기·N/A` · 작업명 끝 `**[폐기 날짜 · 사유]**` |
| `done MOD-NN-NNN "사유"` | 상세표 진행률→100% · 상태→`✅ 완료` · 작업명 끝 `**[✅완료 날짜 · 사유]**` |
| `show` | 상세표 미완(진행률 <100%) 항목만 모듈별 그룹 출력 |

**retire/done 연동 4곳 (상세표 SSOT 재집계):**
1. 상세표 해당 행 (진행률·상태·주석)
2. 레이어1 해당 모듈 **마지막 열 %** = 상세표 모듈 평균 재계산
3. 작성정보 `전체 진행률` % + `완료+폐기 N · 부분 N · 미완 N` 카운트
4. 레이어2 변경 로그 행 append (`주차 | WBS | 사유 | 이전→100% | 마킹`)
- **무결성 검증:** `완료+폐기 + 🟡 + ❌ = 183` — 불일치 시 파일 미수정·중단

**폐기 vs 완료:** 둘 다 진행률 100% (문서 기존 규약 = 폐기간주 100%). 차이는 상태 라벨(⛔ vs ✅), 카운트는 "완료+폐기" 합산.

**안전·사용:**
- `--dry-run` = 파일 미수정·변경 요약만 출력 (실제 적용 전 검증 권장).
- 다건 폐기 = 쉼표 구분 (`retire MOD-18-008,MOD-18-009,MOD-18-010 "약관 동의 가입플로우 통합"`).
- 대상 = `~/.claude/docs/참조문서/간트/` (worktree exemption #5, in-place 단일 항목 — 비가역 낮음).
