`/작업분배` 가 등록한 분배 풀(`DISPATCH.md`)에서 `#tag` 를 **배타적으로 claim** 하고, 해당 분배 문서를 현재 세션 컨텍스트로 로드해 작업을 이어받는다. 한 태그는 한 세션만 점유 — 에이전트팀 다세션 병렬 분배 시 중복 작업을 원천 차단한다. 짝 슬래시 = **`/작업분배`**.

> **경계 — 이 슬래시는 claim + 로드(진입)까지만, 실행이 아니다.** 실제 코드 변경은 claim 후 `/자동진행`·`/실행` 에 위임한다. 계열상 `/작업로드` 의 **다세션·lock 판**이며 `/실행`(내 §계획 step 실행)·`/자동진행`(묶음 승인 실행)과 별개다 — 공통점은 claim 후 그 둘을 호출한다는 것뿐. 프로파일 대비: `/작업시작` = 코드변경 ✗ + lock ✓ / `/실행`·`/자동진행` = 코드변경 ✓ + lock ✗ (정반대).

## 동작 — 인자 분기

| 인자 | 동작 |
|------|------|
| 없음 (`/작업시작`) | DISPATCH.md `available` 목록 출력 (claim 가능 작업) |
| `#tag` (`/작업시작 #auth-jwt`) | 배타적 claim 시도 → 성공 시 분배 문서 본문 로드 + 진입 안내 |
| `#tag done` (`/작업시작 #auth-jwt done`) | claim 한 작업 완료 마킹 (status=done + lock 정리) |

> `#` prefix 는 선택 — `/작업시작 auth-jwt` 도 동일 (`dispatch_tag_sanitize` 가 `#` 제거).

## 세션 식별자 (sid)

```bash
# claim/done 주체 식별 — REGISTRY/lock 의 session_id 앞 8자와 동일 체계.
# Claude Code 가 환경에 노출하지 않으면 Claude 본체가 현재 세션 sid 8자로 치환.
SID8="${CLAUDE_SESSION_ID:0:8}"
[ -z "$SID8" ] && SID8="<현재 세션 sid 8자 — Claude 본체 기입>"
```

> 같은 세션이 일관된 sid 를 써야 `ALREADY_YOURS`/`done` 의 본인 확인이 성립한다.

## ② #tag — 배타적 claim

```bash
source ~/.claude/hooks/lib/dispatch-utils.sh
OUT=$(dispatch_claim "{tag}" "$SID8"); RC=$?
RESULT="${OUT%%|*}"; DOC="${OUT#*|}"
```

`dispatch_claim` 결과별 분기:

| RESULT (rc) | 의미 | 처리 |
|-------------|------|------|
| `CLAIMED` (0) | available → 점유 성공 | 분배 문서(`$DOC`) 본문 출력 + 진입 안내 |
| `ALREADY_YOURS` (0) | 본인이 이미 점유 | 분배 문서 재로드 (이어서 진행) |
| `STOLEN:<old>` (0) | stale(24h+) steal | 분배 문서 로드 + "이전 점유 {old} 24h+ 무응답 → 회수" 경고 |
| `TAKEN:<sid>` (3) | 타 세션 점유 중 | **거부** — "#{tag}는 {sid} 점유 중. 다른 태그 선택 또는 24h 후 재시도" |
| `DONE` (4) | 이미 완료 | **거부** — "#{tag}는 완료됨" |
| `NOTFOUND` (2) | 태그 없음 | available 목록 재출력 + 오타 확인 안내 |

claim 성공(`CLAIMED`/`ALREADY_YOURS`/`STOLEN`) 시:

1. `$DOC` (분배 문서) 전체 본문 Read → 화면 출력 (목표·배경·작업 내용·DoD·대상 파일)
2. 진입 안내:
```
[Claude] #auth-jwt claim 완료 (점유: {sid8}).
        분배 문서: docs/working/dispatch/2026-06-15-be-auth-refactor-auth-jwt.md

        목표: JWT 발급·검증 로직 분리
        대상: app/.../AuthService.php
        작업 4건 / DoD 2건 (본문 참조)

        진입 옵션:
        ① /자동진행 #auth-jwt 작업 일괄 수행      ← 묶음 승인 모드
        ② /분석 부터 단계 진행                     ← working/ 통합 문서 신규
        ③ 개별 지시

        완료 시: /작업시작 #auth-jwt done
```

> claim 후 실제 작업은 worktree 안에서 (CLAUDE.md §4.3 worktree 강제). 분배 문서는 작업 기준 명세 — 진행은 claim 세션이 자신의 working/ 통합 문서를 새로 만들거나(권장: `/분석`~`/실행`) 분배 문서를 직접 기준으로 삼는다.

## ③ #tag done — 완료 마킹

```bash
source ~/.claude/hooks/lib/dispatch-utils.sh
dispatch_done "{tag}" "$SID8"
```

> status=done + `state/dispatch/{tag}/` lock 정리. 분배 작업 종결. (claim 세션의 실제 코드 변경 마무리·머지는 `/작업저장`·`/배포` 영역 — 본 명령은 분배 풀 상태만 종결.)

## §3 Checkpoint 우선 적용

- claim = DISPATCH.md 인덱스 + lock mutation (비가역성 낮음, 회복 가능 — `dispatch_release` 로 available 복귀). 사용자 승인 없이 진행 가능.
- **claim 후 실제 작업**이 §3 매칭(비가역·광범위·외부 시스템)이면 그 시점에 각 guard hook + Echo-Back 이 강제 — 본 슬래시는 claim·로드까지만.
- `done` 마킹은 회복 가능(`dispatch_add` 재등록)하나 타 세션 작업 종결 신호이므로 claim 본인 sid 만 정상 동작.

## SSOT

| SSOT | 역할 |
|------|------|
| `~/.claude/hooks/lib/dispatch-utils.sh` | claim/done/list lib (본 슬래시 = `dispatch_claim`/`dispatch_done`/`dispatch_list` 호출) |
| `~/.claude/docs/working/DISPATCH.md` | 분배 풀 인덱스 (read + lib 경유 갱신) |
| **`~/.claude/commands/작업분배.md`** | **짝 슬래시 — 청크 분해 + 분배 문서 생성 + 태그 등록** |
| `~/.claude/commands/작업로드.md` | 단일 세션 재개 (작업시작=타 세션 이관 claim 과 구분) |
| `~/.claude/commands/자동진행.md` | claim 후 작업 일괄 수행 진입점 |

## 호출 예

```
/작업시작                      ← available 분배 작업 목록
/작업시작 #auth-jwt            ← 배타적 claim + 분배 문서 로드
/작업시작 auth-jwt            ← 동일 (# 생략 가능)
/작업시작 #auth-jwt done      ← 완료 마킹
```
