# RFC 6265 — HTTP Cookie 보안

> 출처: https://httpwg.org/specs/rfc6265.html
> 최종 갱신: 2026-04-08

## 쿠키 보안 속성

### Secure
- HTTPS에서만 쿠키 전송
- 민감 데이터(세션 ID, JWT) 필수 적용
- 주의: 능동적 네트워크 공격자의 HTTP 리다이렉트를 통한 쿠키 주입은 방어 불가

### HttpOnly
- JavaScript(`document.cookie`) 접근 차단
- XSS 공격으로 인한 쿠키 탈취 방지
- 세션 ID, 인증 토큰에 필수 적용

### SameSite
| 값 | 동작 |
|----|------|
| `Strict` | 크로스 사이트 요청 시 쿠키 미전송 |
| `Lax` | 안전한 메서드 + 최상위 네비게이션만 전송 |
| `None` | 모든 요청 전송 (Secure 필수) |

### Domain
- 생략: 요청 호스트에만 쿠키 전송 (가장 안전)
- 명시: 해당 도메인 + 모든 서브도메인에 전송
- 주의: 형제 도메인이 서로의 쿠키를 덮어쓸 수 있음

### Path
- 특정 URL 경로로 쿠키 범위 제한
- **보안 격리에 의존 불가** (RFC 경고) — 비HTTP API가 우회 가능

## 쿠키 접두사

### `__Host-`
가장 엄격: `Secure` 필수 + `Path=/` 필수 + `Domain` 생략 필수

### `__Secure-`
`Secure` 속성 필수. `__Host-`보다 덜 엄격

## RFC 보안 권고

| 권고 | 이유 |
|------|------|
| 쿠키 내용 암호화 + 서명 | HTTPS에서도 변조 방지 |
| 민감 데이터 대신 세션 ID 저장 | 쿠키 탈취 시 피해 최소화 |
| 합리적 만료 시간 설정 | 리플레이 공격 윈도우 축소 |
| HTTPS 전용 사용 | 능동적 공격자의 Set-Cookie 주입 방지 |

## 주요 취약점

- **Ambient Authority**: 쿠키가 자동 첨부되어 CSRF 공격 가능
- **약한 무결성**: 부모 도메인이 자식 도메인 쿠키 손상 가능
- **포트/스킴 격리 부재**: 같은 호스트의 다른 포트/스킴과 쿠키 공유
