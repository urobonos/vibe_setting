# Frontend Functional Spec — 상담사 등록 신청

> Source: 화면설계서 PPTX Slides S446~S451 (6 슬라이드)
> Status: DRAFT
> Updated: 2026-03-24

---

## 1. 개요

| 항목 | 내용 |
|------|------|
| 도메인 | 상담사 등록 신청 (Counselor Registration) |
| 사용자 목표 | 일반 회원이 상담사로 등록하기 위해 기본정보/상담분야/경력/자기소개를 작성하고 약관에 동의하여 신청서를 제출한다 |
| 퍼블리싱 상태 | ❌ 미구현 |
| 기능 연동 상태 | 미연동 |
| i18n 네임스페이스 | `counselorRegistration` |
| 지원 로케일 | `en`, `ko`, `ja` |
| 뷰포트 기준 | 모바일 390x844 (Figma 핸드오프 360px 시안, 구현 PC 최대 430px — `app/[locale]/layout.js`의 SSOT wrapper `max-w-[43rem]`) |
| 슬라이드 수 | 6장 |

### 비즈니스 모델 핵심

- 상담사 등록은 **신청 → 관리자 심사 → 승인/반려** 3단계 프로세스이다.
- 승인 시 상담사 마이메뉴(`/counselor`) 접근 권한이 부여된다.
- 반려 시 사유를 확인하고 재신청할 수 있다.
- 회원가입 완료 후 로그인 상태에서만 신청 가능하다.

### 도메인 흐름 요약

```
상담사 등록 신청 (/counselor-registration)
  ├── [STEP 1] 기본정보 입력 (이름, 연락처, 이메일)
  ├── [STEP 2] 상담분야 선택 (다중 선택)
  ├── [STEP 3] 경력/자격 입력
  ├── [STEP 4] 자기소개 작성
  ├── [STEP 5] 약관 동의 (필수/선택)
  └── [STEP 6] 신청하기 버튼 → 제출
        ├── 신청 완료 화면 (접수 안내)
        └── 심사 상태 확인 (마이메뉴에서)
```

## 2. 라우트 구조

| 라우트 | 파일 경로 | 컴포넌트 | 타입 | i18n 네임스페이스 |
|--------|----------|---------|------|-----------------|
| `/[locale]/counselor-registration` | `app/[locale]/counselor-registration/page.js` | CounselorRegistrationPage | Server → Client | `counselorRegistration` |
| `/[locale]/counselor-registration/complete` | `app/[locale]/counselor-registration/complete/page.js` | CounselorRegistrationComplete | Server → Client | `counselorRegistration` |

### 인증 요구

- **로그인 필수**: 비로그인 상태에서 접근 시 `/[locale]/login?returnUrl=/[locale]/counselor-registration` 리다이렉트.
- **이미 상담사인 경우**: 이미 상담사 등록이 완료된 회원이 접근 시 `/[locale]/counselor`로 리다이렉트.
- **심사중인 경우**: 이미 신청서가 심사 중인 경우 "현재 심사 중입니다" 안내 화면 표시 + 재신청 불가.

## 3. 페이지 정의

### 3-1. 상담사 등록 신청 폼 (슬라이드 S446~S450)

| 항목 | 내용 |
|------|------|
| 라우트 | `/[locale]/counselor-registration` |
| Server Component | `app/[locale]/counselor-registration/page.js` — 메타데이터 생성, labels 구성, 회원 기본정보 사전 로드 |
| Client Component | `app/[locale]/counselor-registration/_components/CounselorRegistrationForm.js` |
| 화면설계서 | S446~S450 |

#### UI 섹션 (상→하 순서)

| # | 섹션 | 설명 |
|---|------|------|
| 0 | 상단 네비게이션 | PageNavBar — 보라색 배경, "상담사 등록 신청" 타이틀 + Home 버튼 |
| 1 | 안내 문구 | 신청 절차 안내 텍스트 (심사 소요 기간 등) |
| 2 | 기본정보 | 이름(실명), 연락처(전화번호), 이메일 — 회원정보에서 사전 채움(pre-fill) |
| 3 | 상담분야 선택 | 다중 선택 체크박스/칩 — 최소 1개 필수 |
| 4 | 경력/자격 입력 | textarea — 상담 경력, 자격증 등 자유 입력 |
| 5 | 자기소개 | textarea — 내담자에게 노출되는 자기소개 |
| 6 | 약관 동의 | 전체 동의 + 개별 약관 체크박스 |
| 7 | 신청하기 버튼 | 보라색 풀폭 CTA 버튼 — 필수 항목 미충족 시 비활성 |

#### 3-1-1. 기본정보 (STEP 1)

| 필드 | 라벨 | 타입 | 필수 | 사전채움 | 제한 |
|------|------|------|------|---------|------|
| 이름 | "이름 (실명)" | text input | O | 회원가입 시 입력한 이름 | 2~20자, 특수문자 불가 |
| 연락처 | "연락처" | tel input | O | 회원가입 시 입력한 전화번호 | 국가별 전화번호 포맷 |
| 이메일 | "이메일" | email input | O | 회원가입 시 입력한 이메일 | 이메일 포맷 검증 |

- 사전채움된 값은 수정 가능하다 (상담사 등록용 별도 연락처를 사용할 수 있으므로).
- 이메일은 회원가입 이메일과 동일해야 하는지, 별도 입력 가능한지는 기획 확인 필요.

#### 3-1-2. 상담분야 선택 (STEP 2)

| 분야 | 설명 |
|------|------|
| 영감영시 | 영적 감각 기반 상담 |
| 타로 | 타로 카드 상담 |
| 사주성명 | 사주/성명학 상담 |

- **최소 1개** 이상 선택 필수.
- **다중 선택** 가능 (최대 제한 없음, 또는 관리자 설정).
- 칩(Chip) 또는 체크박스 UI로 표시.

#### 3-1-3. 경력/자격 입력 (STEP 3)

| 필드 | 라벨 | 타입 | 필수 | 제한 |
|------|------|------|------|------|
| 경력/자격 | "경력 및 자격사항" | textarea | O | 최소 10자 ~ 최대 1,000자 |

- 상담 관련 경력, 자격증, 수료 내역 등을 자유 형식으로 입력.
- 글자 수 카운터 표시 (현재/최대).

#### 3-1-4. 자기소개 (STEP 4)

| 필드 | 라벨 | 타입 | 필수 | 제한 |
|------|------|------|------|------|
| 자기소개 | "자기소개" | textarea | O | 최소 20자 ~ 최대 2,000자 |

- 승인 후 상담사 프로필에 노출되는 자기소개 텍스트.
- 글자 수 카운터 표시 (현재/최대).
- "내담자분들께 보여지는 소개 글입니다. 정성스럽게 작성해주세요." 안내 텍스트.

#### 3-1-5. 약관 동의 (STEP 5)

| 약관 | 필수 여부 | 설명 |
|------|---------|------|
| 전체 동의 | — | 모든 약관 일괄 체크/해제 |
| 상담사 이용약관 | 필수 | 상담사 서비스 이용에 관한 약관 |
| 개인정보 수집 및 이용 동의 | 필수 | 신청 심사를 위한 개인정보 수집 동의 |
| 수수료 정책 동의 | 필수 | 플랫폼 수수료 비율 및 정산 정책 동의 |
| 마케팅 정보 수신 동의 | 선택 | 프로모션/이벤트 정보 수신 |

- "전체 동의" 체크 시 모든 약관 일괄 체크.
- "전체 동의" 해제 시 모든 약관 일괄 해제.
- 개별 약관 해제 시 "전체 동의" 자동 해제.
- 모든 개별 약관 체크 시 "전체 동의" 자동 체크.
- 약관 내용 보기: 각 약관 항목 옆 "보기" 링크 → 약관 상세 바텀시트 또는 새 페이지.

#### 3-1-6. 신청하기 버튼 (STEP 6)

| 상태 | 조건 | UI |
|------|------|-----|
| 비활성 | 필수 필드 미충족 또는 필수 약관 미동의 | 회색 배경, 클릭 불가 (`disabled`) |
| 활성 | 모든 필수 필드 입력 + 필수 약관 동의 | 보라색 배경 (`bg-[var(--purple-1)]`) |

- 활성 상태에서 클릭 시 최종 확인 알럿: "상담사 등록을 신청하시겠습니까?"
- 확인 → API 호출 → 성공 시 완료 화면으로 이동.

## 5. API 연동

> **⚠️ 이 섹션의 API 엔드포인트/필드명은 추정값입니다. 실제 값은 `docs/specs/API_FIELD_MAP.md` 참조.**


| 엔드포인트 | Method | Request Body | Response |
|-----------|--------|-------------|----------|
| `/api/counselor/getRegistrationStatus` | POST | `{ locale }` | `{ response, status: 'none'|'pending'|'approved'|'rejected', rejectedReason? }` |
| `/api/counselor/register` | POST | `{ name, phone, email, fields[], career, introduction, agreements }` | `{ response, message }` |
| `/api/counselor/getPreFillInfo` | POST | `{ locale }` | `{ response, name, phone, email }` |

## 6. 상태 관리

- `useAuthStore`: 로그인 상태, 사용자 역할 확인
- 로컬 상태 (`useState`):
  - 이름, 연락처, 이메일 (사전채움 후 수정 가능)
  - 선택된 상담분야 배열
  - 경력/자격 텍스트
  - 자기소개 텍스트
  - 약관 동의 상태 (개별 + 전체)
  - 각 필드 에러 메시지
  - 제출 로딩 상태 (`isSubmitting`)

## 8. 에러 처리

| 에러 케이스 | 처리 방식 |
|-----------|---------|
| 비로그인 접근 | `/[locale]/login?returnUrl=...` 리다이렉트 |

| 제출 API 실패 | 에러 알럿 + 입력 데이터 보존 (재시도 가능) |
| 세션 만료 | 로그인 페이지 리다이렉트 (입력 데이터 유실 경고) |

| 항목 | 구현 |
|------|------|
| 폼 필드 | `<label>` + `htmlFor` 연결, `aria-required="true"` |

| 확인 다이얼로그 | `role="alertdialog"`, `aria-modal="true"` |

## 10. 성능 고려사항

| 항목 | 전략 |
|------|------|
| 사전채움 | page.js(Server)에서 회원정보 fetch → Client에 props 전달 (1회 호출) |
| 유효성 검증 | 클라이언트 실시간 검증 (onChange) + 서버 최종 검증 (onSubmit) |
| 제출 중복 방지 | `isSubmitting` 상태로 버튼 비활성 + API 중복 호출 차단 |
| 입력 데이터 보존 | 페이지 이탈 시 `beforeunload` 경고 (입력 내용이 있을 때) |
