## 1. Introduction

### 1.1 Purpose

This document specifies the software requirements for the Chat Module of HongCafe Global Backend in conformance with IEEE 29148:2018. The Chat Module is responsible for real-time consultation chat connection and management, timing control, goods-chat estimate workflow, shop-chat O2O sessions, and integration with the SendBird messaging platform.

Intended readers of this SRS are identified in the table below.

| Reader Group | Role |
|---|---|
| Backend Developer | Implementation reference for FR and NFR |
| Frontend Developer | API contract and error code reference |
| QA Engineer | Verification criteria and acceptance conditions |
| System Architect | Constraint and design boundary reference |
| Project Manager | Stakeholder scope confirmation |

### 1.2 Scope

**System Name:** Chat Module — HongCafe Global Backend

**Included Scope:**
- Chat: 44 endpoints (ChatController) — item list, chat connect, timing, message, file, status management
- GoodsChat: 6 endpoints (GoodsChatController) — product inquiry chat, estimate workflow
- ShopChat: 2 endpoints (ShopChatController) — O2O in-person consultation chat
- SendBird real-time messaging platform integration
- Hermes call-record integration, FCM push notification, AWS S3 file storage integration

**Excluded Scope:**
- Payment and settlement processing (Commerce Module)
- Member authentication and authorization (Member Module)
- SendBird client SDK implementation (Frontend responsibility)

**Total Endpoints:** 52

### 2.4 Design and Implementation Constraints

| Constraint ID | Constraint | Rationale |
|---|---|---|
| CON-001 | SendBird API Token managed only via environment variable `SENDBIRD_API_TOKEN`. Hardcoding in source code is prohibited | OWASP API8:2023 Security Misconfiguration |
| CON-002 | Chat room code format is fixed: `CHAT-{YYYYMMDDHHmmss}-{XXX}` (random 3 characters) | Legacy compatibility and readability |
| CON-003 | On estimate cancellation, `gs_status=4` is terminal. Transition from cancelled state to any other state is prohibited (unidirectional FSM) | Business rule integrity |
| CON-004 | ChatRepository has 88 methods in legacy-integrated state. Immediate decomposition is prohibited due to operational risk | Incremental migration strategy |
| CON-005 | Auto Routing disabled (`setAutoRoute(false)`). All endpoints must be explicitly registered in Routes.php | Security policy |
| CON-006 | Authentication: JWT (`hc_access` HttpOnly cookie) + CSRF (`X-CSRF-TOKEN` header, POST/PUT/DELETE) | Security policy |
| CON-007 | Date and time: `DateTimeImmutable` is mandatory. `date()` and `time()` are prohibited | Coding standard |
| CON-008 | API response: DB `snake_case` must be converted to API `camelCase` | API response standard |

## 3. Functional Requirements

Each FR includes Input Validation and Verification Method per IEEE 29148:2018 §5.2.4.

### FR-001: Item List and Search

**Description:** Provides PC list formatting (sorting, phone number placement, comment mapping, tag/notice/point formatting) and mobile list retrieval (5 sort types: suggest / itemNew / recent / calling / hot).

| Item | Content |
|---|---|
| Related EPs | `POST /api/chats/get-list-pc`, `POST /api/chats/get-list-mobile`, `POST /api/chats/get-list-comment`, `POST /api/chats/get-item` |
| Input Validation | Sort parameter must be one of: `suggest`, `itemNew`, `recent`, `calling`, `hot`. Invalid values default to `suggest` |
| Precondition | None (includes public EPs; JWT is optional for some) |
| Postcondition | Returns sorted item array. Returns empty array on SendBird error (Graceful Degradation) |
| Verification Method | Unit test: `ChatListService::buildPcItemList()` — sort logic, tag formatting, phone number masking |

### FR-002: Chat Connect and Room Creation

**Description:** Performs chat room creation, coin deduction, Hermes call record registration, and timer initialization. Pre-validates blocked, rejected, absent, and on-call states.

| Item | Content |
|---|---|
| Related EPs | `POST /api/chats/chat-connect`, `POST /api/chats/chat-timer`, `POST /api/chats/chat-start` |
| Input Validation | `ce_code` required, DB existence check. `ac_id` validated via JWT. Coin balance checked; insufficient balance returns 400. Callee on-call status (`onFlag`) must be `on` or `standby` |
| Precondition | JWT authentication complete, sufficient coin balance, callee on-call status (`on` or `standby`) |
| Postcondition | `tb_chat_rooms` record created, `room_code` issued (`CHAT-YYYYMMDDHHmmss-XXX`), Hermes call record registered |
| Error Conditions | Blocked: 403 `REJECTED`, insufficient coins: 400 `INSUFFICIENT_COIN`, callee offline: 409 `CALLEE_OFFLINE`, callee on call: 409 `CALLEE_ON_CALL` |
| Verification Method | Integration test: end-to-end normal connection flow. Unit test: per-error-condition branch validation |

### FR-003: Chat Timing and Time Extension

**Description:** Provides remaining time retrieval, time extension request (Caller to Callee), extension approval or rejection (Callee to Caller), time alerts, and close alerts.

| Item | Content |
|---|---|
| Related EPs | `POST /api/chats/get-remain-time`, `POST /api/chats/chat-request-time-add`, `POST /api/chats/chat-time-add`, `POST /api/chats/time-alert`, `POST /api/chats/close-alert` |
| Input Validation | `room_code` format validated (`CHAT-` prefix required). Extension time (seconds) must be a positive integer. Room participant ownership validated (`ac_id` or `ce_code` match) |
| Precondition | Valid chat session exists (`cr_status = 'on'`) |
| Postcondition | Returns remaining time in seconds; `cr_add_time` updated on extension approval |
| NFR Link | NFR-002 (second-level timing accuracy) |
| Verification Method | Unit test: `get-remain-time` return value validated for UTC-based second-level accuracy |

### FR-004: Chat Status Management

**Description:** Performs absence detection (5-minute no-response), disconnect confirmation, chat close, and connection status check. Supports bidirectional state tracking for Caller and Callee.

| Item | Content |
|---|---|
| Related EPs | `POST /api/chats/absence-check`, `POST /api/chats/disconnect-check`, `POST /api/chats/chat-closed`, `POST /api/chats/connect-check`, `POST /api/chats/check-absence` |
| Input Validation | `room_code` required. Requester identity verified via JWT. Absence threshold: 300 seconds (5 minutes) elapsed since last response |
| Precondition | Chat session is active |
| Postcondition | `cr_status` automatically updated on absence detection. On close: Hermes `updateChatClose()` called, settlement triggered |
| NFR Link | NFR-006 (5-minute absence detection) |
| Verification Method | Unit test: boundary value validation at 5-minute threshold (299 s: no absence, 300 s: absence) |

### FR-005: Message and File Management

**Description:** Provides message log storage (v1 and v2 APIs), read marking, and file upload and download (S3 integration).

| Item | Content |
|---|---|
| Related EPs | `POST /api/chats/message-log`, `POST /api/chats/message-log-v2`, `POST /api/chats/mark-as-read`, `POST /api/chats/file-upload`, `POST /api/chats/upload-chat-file`, `GET /api/chats/chat-file-down` |
| Input Validation | File upload: dual MIME type validation required (file extension + `mime_content_type()`). Allowed MIME type whitelist enforced. File size upper limit validated |
| Precondition | JWT authentication complete, valid chat session |
| Postcondition | Message stored in DB; file URL returned on successful S3 upload |
| NFR Link | NFR-005 (file upload security) |
| Verification Method | Unit test: allowed and disallowed MIME type validation. Integration test: S3 upload end-to-end |

### FR-006: Favorites, Q&A, and Price Management

**Description:** Provides favorites add and delete (JWT-authenticated), Q&A registration (with FCM notification to callee), and item price modification (with change history log).

| Item | Content |
|---|---|
| Related EPs | `POST /api/chats/chat-add-like`, `DELETE /api/chats/chat-delete-like`, `POST /api/chats/insert-item-qna`, `POST /api/chats/save-item-price` |
| Input Validation | Favorites: `it_code` existence verified in DB. Q&A: question content must not be empty. Price: must be a positive integer |
| Precondition | JWT authentication complete |
| Postcondition | Favorites saved or deleted in DB. Q&A saved and callee FCM notification sent. Price change log recorded |
| Verification Method | Unit test: FCM notification mock validation. Duplicate favorites prevention validation |

### FR-007: Posting Retrieval

**Description:** Provides posting list, detail view (with previous/next navigation), and comment list retrieval.

| Item | Content |
|---|---|
| Related EPs | `POST /api/chats/get-posting-list`, `POST /api/chats/posting-detail`, `POST /api/chats/get-posting-comments` |
| Input Validation | Page parameter: must be a positive integer. `per_page` maximum value limited to 100 |
| Precondition | None (public EPs) |
| Postcondition | Response includes pagination metadata: `currentPage`, `perPage`, `total`, `lastPage` |
| Verification Method | Unit test: first page and last page navigation previous/next pointer validation |

### FR-008: GoodsChat (6 EPs)

**Description:** Provides product inquiry chat room creation (via ChatConnectionService), estimate workflow (send, retrieve, cancel), SendBird message integration, and O2O shop (`SH-` prefix) support.

| Item | Content |
|---|---|
| Related EPs | `POST /api/goods-chats/chat-connect`, `POST /api/goods-chats/send-estimate`, `POST /api/goods-chats/get-estimate`, `POST /api/goods-chats/cancel-estimate`, `POST /api/goods-chats/update-estimate-message-id`, `POST /api/goods-chats/callee-chat-connect` |
| Input Validation | `gd_code` required; product existence and active status verified in DB. Estimate amount: positive integer. On cancellation, `gs_status` pre-state checked (cancellation from status 4 is prohibited) |
| Precondition | JWT authentication complete. Product and callee existence confirmed |
| Postcondition | SendBird group channel created, `tb_chat_rooms` record created, `tb_goods_sell` estimate record created. On cancellation: `gs_status=4`, `cancel_date` recorded |
| FSM States | `gs_status`: 0 (pending) → 1 (confirmed) → 2 (work complete) → 3 (purchase confirmed), cancelled = 4 (unidirectional, non-reversible) |
| Verification Method | Unit test: FSM state transition validation. Abnormal transition (cancelled to confirmed, etc.) rejection confirmed |

### FR-009: ShopChat (2 EPs)

**Description:** Creates in-person consultation chat rooms. Configures SendBird three-party channel (admin + Callee + Caller). Supports callee initialization.

| Item | Content |
|---|---|
| Related EPs | `POST /api/shop-chats/chat-connect`, `POST /api/shop-chats/callee-chat-connect` |
| Input Validation | `sh_code` required; shop existence verified in DB. Callee permission filter (`role:callee`) applied to `callee-chat-connect` |
| Precondition | JWT authentication complete, shop record exists |
| Postcondition | SendBird group channel with three parties (`admin`, `ce_code`, `ac_id`) created; `tb_chat_rooms` record created with `cr_type='shop'` |
| Verification Method | Integration test: three-party channel membership validation. `role:callee` filter application on `callee-chat-connect` verified |

### FR-010: Callee Chat Management

**Description:** Provides callee favorites list retrieval, greeting modification, callee on-call status query, and remaining coin check.

| Item | Content |
|---|---|
| Related EPs | `POST /api/chats/get-callee-chat-like-list`, `POST /api/chats/update-greeting`, `POST /api/chats/get-callee-status`, `POST /api/chats/get-remain-coin` |
| Input Validation | `role:callee` filter applied to `update-greeting`. Greeting content length limit validated |
| Precondition | JWT authentication complete |
| Postcondition | Greeting updated in DB. Status and coin information returned |
| Verification Method | Unit test: non-callee user receives 403 on role-protected EPs |

## 4. Non-Functional Requirements

Each NFR includes quantitative measurement criteria and a verification method per IEEE 29148:2018 §5.2.6.

### NFR-001: SendBird API Response Performance

| Item | Content |
|---|---|
| Requirement | SendBird REST API calls (channel creation, message delivery) must respond within 2 seconds |
| Quantitative Criterion | P95 response time ≤ 2,000 ms. P99 ≤ 5,000 ms |
| Measurement Method | Aggregate cURL response times from APM (Application Performance Monitoring) logs |
| Verification Method | Load test: P95 measured at 50 concurrent users |
| Failure Response | On timeout: return empty array + log error (Graceful Degradation) |

### NFR-002: Chat Timing Accuracy

| Item | Content |
|---|---|
| Requirement | Chat remaining time calculation accurate to the second |
| Quantitative Criterion | Deviation within ±1 second relative to server UTC time |
| Measurement Method | Compare `get-remain-time` API response against DB `cr_start_time` + `cr_add_time` calculation |
| Verification Method | Unit test: boundary values (0 s, 1 s, 300 s) validated with UTC timezone enforced |

### NFR-003: Chat Room Access Security

| Item | Content |
|---|---|
| Requirement | All chat-room-related EPs must verify that the requester is a participant (matching `ac_id` or `ce_code`) |
| Quantitative Criterion | 100% 403 `FORBIDDEN` returned for non-participant requests |
| Measurement Method | Security test: request with another user's `room_code`, observe response code |
| Verification Method | Unit test: ownership condition in Repository query validated. OWASP API1:2023 (BOLA) mitigation confirmed |

### NFR-004: SendBird Failure Isolation (Graceful Degradation)

| Item | Content |
|---|---|
| Requirement | Core Chat Module functions (excluding chat connect) must remain available during SendBird API failures |
| Quantitative Criterion | Empty array returned for list EPs at 100% rate on SendBird error. Service-wide outage 0% |
| Measurement Method | Inject SendBird API failure via mock, observe list EP response |
| Verification Method | Integration test: SendBird API mock failure injected; list EP returns HTTP 200 with empty array |

### NFR-005: File Upload Security

| Item | Content |
|---|---|
| Requirement | Chat file uploads must pass dual MIME type validation (extension + `mime_content_type()`) before S3 storage |
| Quantitative Criterion | 0% success rate for disallowed MIME type file uploads |
| Measurement Method | Attempt upload of file with disallowed MIME type, observe response code |
| Verification Method | Unit test: image and PDF allowed, executable files rejected |

### NFR-006: Absence Detection Threshold

| Item | Content |
|---|---|
| Requirement | Automatic absence processing triggered after 5 minutes (300 seconds) of participant inactivity |
| Quantitative Criterion | 100% absence processing when last response exceeds 300 s. 0% absence processing at 299 s or less |
| Measurement Method | Validate timestamp comparison logic in `absence-check` EP |
| Verification Method | Unit test: boundary values validated (299 s, 300 s, 301 s) |

## 6. Use Cases

### UC-001: Full Chat Session Lifecycle

| Item | Content |
|---|---|
| Use Case ID | UC-001 |
| Actors | Caller (user), Callee (consultant) |
| Related FRs | FR-002, FR-003, FR-004, FR-005 |

**Normal Flow:**

| Step | Actor | Action |
|---|---|---|
| 1 | Caller | `POST /api/chats/chat-connect` request; JWT auth, coin balance, callee status validated |
| 2 | System | Block check → Hermes call record registered → `tb_chat_rooms` created → `room_code` issued |
| 3 | Caller | `POST /api/chats/chat-timer` timer initialized |
| 4 | Caller | `POST /api/chats/chat-start` chat started (memo, prior consultation history retrieved) |
| 5 | Both | `POST /api/chats/message-log`, `POST /api/chats/file-upload` conversation in progress |
| 6 | System | Remaining time low → `POST /api/chats/time-alert` notification sent |
| 7 | Caller | `POST /api/chats/chat-request-time-add` time extension request |
| 8 | Callee | `POST /api/chats/chat-time-add` extension approved or rejected |
| 9 | Both | `POST /api/chats/chat-closed` close → `POST /api/chats/close-alert` → settlement processed |

**Alternative Flow:**
- 5-minute no-response: `POST /api/chats/absence-check` → automatic absence processing → Hermes `updateChatMiss()`

**Error Flow:**
- Blocked user: 403 `REJECTED`
- Insufficient coins: 400 `INSUFFICIENT_COIN`
- Callee offline: 409 `CALLEE_OFFLINE`
- Callee on call: 409 `CALLEE_ON_CALL`

### UC-002: Estimate Workflow

| Item | Content |
|---|---|
| Use Case ID | UC-002 |
| Actors | Callee (estimate sender), Caller (confirm or cancel) |
| Related FRs | FR-008 |

**Normal Flow:**

| Step | Actor | Action |
|---|---|---|
| 1 | Callee | `POST /api/goods-chats/send-estimate` — `tb_goods_sell` record created (`gs_status=0`) |
| 2 | System | Estimate message sent to SendBird channel → `messageId` stored |
| 3 | Caller | `POST /api/goods-chats/get-estimate` — estimate information retrieved |
| 4 | Caller | Estimate confirmed → `gs_status=1` updated → purchase confirmed → `gs_status=3` |

**Alternative Flow:**
- Caller cancellation: `POST /api/goods-chats/cancel-estimate` → `gs_status=4`, `cancel_date` recorded
- `update-estimate-message-id`: SendBird `messageId` updated asynchronously (ensures consistency)

**FSM State Transitions:**
```
0 (pending) → 1 (confirmed) → 2 (work complete) → 3 (purchase confirmed)
    \________________________________> 4 (cancelled, unidirectional)
```

## 9. Feasibility Review

> Basis: OWASP API Security Top 10 2023, GoF Design Patterns (Gamma et al., 1994), SendBird Platform API official documentation, IEEE 29148:2018

| Review ID | Topic | Conclusion | Rationale | Alternative | Trade-offs |
|---|---|---|---|---|---|
| FEA-001 | SendBird vs. self-hosted WebSocket | Retain SendBird | Operating a WebSocket server on EC2 incurs continuous load and failure-response costs that exceed SaaS subscription fees. SendBird has built-in channel permission controls addressing OWASP API3:2023. Channel membership management, message history, and read-status features available immediately | Socket.io + Redis Pub/Sub self-implementation | Cost reduction possible but operational complexity increases dramatically. Internal failure response required |
| FEA-002 | Real-time timing accuracy feasibility | Client polling achieves NFR-002 | DB `CURRENT_TIMESTAMP` + server UTC timezone enforced. Client `get-remain-time` polling interval can be set below 1 second. Server-based calculation eliminates client clock drift | WebSocket push (server-initiated) | Polling: simple implementation, predictable load. WebSocket: superior real-time performance but complex connection management |
| FEA-003 | ChatConnectionService callback pattern (GoF Strategy variant) | Appropriate design choice | GoodsChat and ShopChat differ only in "existing room lookup" logic; remaining flow (block check → channel creation → code issuance → DB save) is identical. PHP callable injection is more concise than Template Method. Mock callable injection enables easy unit testing (OWASP API10:2023 mitigation) | Direct implementation in each Controller (3x duplication) | Callback: high flexibility, type safety requires explicit Interface. Template Method: type-safe but increases class count |
| FEA-004 | Estimate workflow unidirectional FSM | Design is sound | `gs_status` unidirectional transitions (0 to 4 maximum). Post-cancellation non-reversibility enforced by DB UNIQUE constraint + application-level validation. OWASP API6:2023 mitigation — state transitions controlled server-side only | Allow free state transitions | Unidirectional FSM: business integrity guaranteed. Complex restore scenarios not supported (not in requirements) |
| FEA-005 | 5-minute absence threshold and polling approach | Client polling is appropriate | Client polls `absence-check` EP periodically. Server processes absence when 300 s have elapsed since last response timestamp. No cron required; implementation is simple. Detection delay on client network failure is acceptable | Server-side cron-based auto-processing | Polling: immediate response, client-dependent. Cron: server-driven, resilient to network failure. Polling is appropriate for current requirements |
