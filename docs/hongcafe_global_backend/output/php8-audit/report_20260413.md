## 위반 유형별 분류

### 1. DI 규칙 위반 — `new` 직접 호출 (H: ~45건)

프로젝트 전반에서 가장 빈번한 위반. `service()` 대신 `new` 키워드로 직접 인스턴스화.

| 패턴 | 발생 모듈 | 건수 |
|------|----------|------|
| `new \App\Libraries\Fcm()` | Member, Call, Chat, Commerce, Payment | ~12건 |
| `new \App\Libraries\Communicator\Sms()` | Auth, Member, Chat | ~5건 |
| `new \App\Libraries\SendMail\TempleteMail()` | Auth, Member | ~3건 |
| `new \App\Models\*Model()` | Call, Chat, Commerce, Payment, Reservation | ~15건 |
| `new ServiceController\Hermes()` | Chat, Content, Commerce, Payment | ~5건 |
| `new \App\Modules\Chat\Controllers\*()` | Commerce | ~4건 |
| `new ItemListFormatter()` (Services.php 등록 있음에도) | Commerce | 3건 |

**수정 방향:** `service()` 함수 또는 생성자 주입으로 전환. 레거시 Libraries는 Shared/Services로 래핑 후 Interface 추상화.

### 2. 모듈 경계 위반 — Interface Only 원칙 (H: ~20건)

| 위반 패턴 | 발생 위치 |
|-----------|----------|
| Repository에서 다른 모듈 Controller를 `new`로 직접 인스턴스화 | Chat/ChatRepository, Content/ThemeRepository, Commerce/ItemsRepository, Commerce/SpecialPriceRepository, Payment/PaybackRepository |
| Controller에서 다른 모듈 Controller를 `new`로 직접 인스턴스화 | Commerce/Goods, Commerce/Shop |
| Controller에서 구체 Service/Repository 클래스를 타입 선언 | Chat 3개 Controller, Content 3개 Controller, Call/Pbx, Event/Roulette |
| Service에서 구체 Repository 클래스 직접 참조 | Chat/ChatConnectionService, Commerce/ShopReservationService |

**수정 방향:** 모든 모듈 간 참조를 Interface 타입으로 전환. `ServiceController\Hermes` 패턴은 `HermesServiceInterface` 경유로 통일.
