## 4. 구조적 이슈

### 4-1. 중복 테스트 구조

```
tests/
├── Modules/{BC}/Unit/     ← 신규 모듈 테스트 (Controller method_exists)
├── Modules/{BC}/Feature/  ← 신규 Feature 테스트 (라우트 불일치)
├── unit/Models/           ← 레거시 모델 테스트 (메서드 변경/삭제)
├── unit/Libraries/        ← 레거시 라이브러리 테스트 (대부분 정상)
└── unit/Filters/          ← 필터 테스트 (1건 에러)
```

레거시 `tests/unit/Models/`는 모듈화 이전 코드 기준. 모델 메서드가 Repository로 이동되면서 대량 에러 발생.

### 4-2. 테스트 누락 영역

| 영역 | 테스트 유무 | 중요도 |
|------|-----------|--------|
| Repository 레이어 | 없음 | 높음 — DB 쿼리 검증 |
| Entity/VO | 없음 | 중간 — 값 객체 불변성 |
| RateLimitFilter | 없음 | 높음 — 429 응답 + 카운터 |
| AuthFilter | 없음 | 높음 — JWT/API Key/Session 분기 |
| RoleFilter | 없음 | 높음 — RBAC 역할 차단 |
| BaseApiController 헬퍼 | 없음 | 중간 — respondSuccess/respondPaginated |
