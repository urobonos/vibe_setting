## 공통 패턴

잔여 6개 모듈 모두에서 동일한 구조적 불일치 패턴이 확인됨.

### 패턴 A — IEEE "목표 설계" vs 실제 "레거시 RPC"
SRS/SDD/IDD가 RESTful 설계(`GET /api/reservations/{id}`, `GET /api/services`, `GET /share/profile/{userId}`)로 작성된 반면, 실제 Routes.php + 코드는 동사 포함 kebab-case RPC(`POST /api/reservations/get-my-reservation`, `POST /api/services/get-service-list-mobile`, `POST /api/sns-shares/profile-sns`)로 구현. notification·social·service·reservation·payment에서 모두 관찰.

→ SSOT 결정(API=SSOT)에 따라 **IEEE 산출물 대부분을 실제 API 패턴으로 재작성**해야 함.

### 패턴 B — Refresh Token Path 갱신 누락
커밋 `a7be0b5 fix(auth): Refresh Token 쿠키 Path를 /auth/refresh에서 /로 확대`가 반영되지 않은 API md/yaml이 **6개 모듈 모두에서 확인**. 하위 commerce(goods/items/shop) 각각에서도 재발. 표준 일괄 수정이 필요하며, IEEE 쪽 auth-api 관련 서술도 확인 필요.

→ 이는 [A]가 아닌 [B] (API 내부 미동기화). md/yaml 일괄 sed 가능.

### 패턴 C — DateTimeImmutable 강제 위반
reservation, social, shop 모듈 여러 Controller에서 `date()`/`time()`/`strtotime()` 사용이 확인됨. CLAUDE.md 코딩 표준(`DateTimeImmutable` 강제) 위반. 이는 IEEE 수정이 아닌 **코드 리팩토링** 대상.

### 패턴 D — SRS "JWT 필수" vs 실제 공개 EP
notification·service·reservation·items에서 SRS가 JWT 필수로 명시했으나 실제 Routes.php에는 `auth` 필터 미적용인 EP 발견. 이 중 일부는 의도된 공개 EP(`get-schedule`, `calendars/calendar`, `get-item`)이고 일부는 **보안 취약점**(service의 `save-reject`·`delete-reject`).

## 페이즈 2 진입 권고

### 트랙 A — IEEE 문서 일괄 업데이트 (gate=1로 진행 가능)
- **범위**: 6개 모듈 × (SRS/SDD/IDD/STD 최대 4종) = 최대 24건 문서 업데이트
- **주 작업**: 모든 EP 정의·요청 파라미터·응답 스키마·매핑 테이블을 실제 Routes.php + Controller 기준으로 재작성
- **예상 규모**: notification·social·service·reservation 4개 모듈은 SRS/SDD/IDD 섹션 다수 재작성. commerce·payment는 부분 수정. 전체 30~50 커밋 예상
- **커밋 전략**: 모듈별 × 문서 타입별 묶음 (예: `docs(specs): reservation-srs v2.0 — API 현황 전면 반영`)
- **트레이드오프**: IEEE 재작성 중 "목표 설계"였던 내용이 영구 상실될 수 있음 → 별도 `docs/specs/archive/20260421-legacy-design-intent/`에 백업 후 재작성 권고

### 트랙 B — API 내부 정합성 + 보안 수정 (gate=2 필요)
- **B-1 보안 Critical (즉시)**: `Config/Routes.php`에서 `save-reject`/`delete-reject`에 `auth` + `csrftoken` 필터 추가 — SERVICE-DEF-004
- **B-2 Refresh Token Path 일괄**: 6개 모듈 md/yaml의 `/api/auth/refresh` → `/` 치환 (단순 sed)
- **B-3 DateTimeImmutable 리팩토링**: reservation·social·shop 각 Controller — 별도 세션 권고 (범위 큼)
- **B-4 기타 API 내부 불일치 20건**: md vs yaml 필드명, 응답 구조, 에러 코드 등 — 모듈별 개별 처리
