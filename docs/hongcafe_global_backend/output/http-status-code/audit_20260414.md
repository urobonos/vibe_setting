## 1. 프로젝트 API 응답 표준 (CLAUDE.md 기준)

```
성공: { "data": {...} }                                        → HTTP 200/201
에러: { "error": { "code": "...", "message": "..." } }         → HTTP 4xx/5xx
```

- HTTP 상태코드가 성공/실패의 SSOT (Single Source of Truth)
- 에러 코드: 현상 서술형, suffix 없음 (`INVALID_INPUT`, `NOT_FOUND`, `UNAUTHORIZED`, `FORBIDDEN`, `CONFLICT`, `INTERNAL`)

## 2. 표준 응답 메서드 (BaseApiController)

| Status | 메서드 | Error Code | 기본 메시지 (lang key) |
|--------|--------|------------|------------------------|
| 200 | `respondSuccess()` | — | (없음) |
| 201 | `respondCreated()` | — | (없음) |
| 200 | `respondSuccessWithMeta()` | — | (없음) |
| 400 | `respondValidationError()` | `INVALID_INPUT` | `Error.invalidInput` |
| 401 | `respondUnauthorized()` | `UNAUTHORIZED` | `Error.unauthorized` |
| 404 | `respondNotFound()` | `NOT_FOUND` | `Error.notFound` |
| 500 | `respondServerError()` | `INTERNAL` | `Error.internal` |

> `respondError(string $code, string $message, int $httpStatus, array $details)` 범용 메서드로 403, 409 등도 처리

## 4. Status Code별 종합 정리

### 4-1. 현행 유지 (표준 준수)

| Status | Error Code | 현재 메시지 | RFC 9110 표준 의미 | 판정 |
|--------|------------|-------------|---------------------|------|
| **200** | — | (data 반환) | OK — 요청 성공 | 적절 |
| **201** | — | (data 반환) | Created — 리소스 생성 완료 | 적절 |
| **400** | `INVALID_INPUT` | `lang('Error.invalidInput')` | Bad Request — 클라이언트 요청 오류 | 적절 |
| **401** | `UNAUTHORIZED` | `lang('Error.unauthorized')` | Unauthorized — 인증 자격 없음 | 적절 |
| **403** | `FORBIDDEN` | (컨텍스트별 메시지) | Forbidden — 인가 거부 | 적절 |
| **404** | `NOT_FOUND` | `lang('Error.notFound')` | Not Found — 리소스 미존재 | 적절 |
| **405** | `METHOD_NOT_ALLOWED` | 허용되지 않은 HTTP 메서드입니다. | Method Not Allowed | 적절 — Allow 헤더 포함 |
| **409** | `CONFLICT` | (컨텍스트별 메시지) | Conflict — 리소스 상태 충돌 | 적절 |
| **429** | `TOO_MANY_REQUESTS` | 요청 한도를 초과하였습니다. | Too Many Requests (RFC 6585) | 적절 — Retry-After 헤더 포함 |
| **500** | `INTERNAL` | `lang('Error.internal')` | Internal Server Error | 적절 |
