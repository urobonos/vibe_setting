## 1. 응답 포맷

### 성공 응답

```json
// 200 OK — 단일 데이터
{ "data": {...} }

// 200 OK — 데이터 + 메시지
{ "data": {...}, "message": "처리 완료" }

// 200 OK — 목록 + 페이지네이션
{
  "data": [...],
  "meta": { "currentPage": 1, "perPage": 20, "total": 100, "lastPage": 5 }
}

// 201 Created — 리소스 생성
{ "data": {...} }
```

### 에러 응답

```json
// 4xx / 5xx 에러
{
  "error": {
    "code": "INVALID_INPUT",
    "message": "입력값이 유효하지 않습니다."
  }
}

// Validation 에러 (필드별 상세)
{
  "error": {
    "code": "INVALID_INPUT",
    "message": "입력값이 유효하지 않습니다.",
    "details": {
      "ac_id": "이메일 형식이 아닙니다.",
      "ac_password": "비밀번호는 8자 이상입니다."
    }
  }
}
```

> **HTTP 상태코드가 성공/실패의 SSOT.** 응답 body에 별도 status/response 필드를 넣지 않는다.

## 2. Status Code + Error Code 일람

### 2xx 성공

| Status | 메서드 | 용도 | 응답 body |
|--------|--------|------|-----------|
| **200** | `respondSuccess($data, $message)` | 조회, 수정, 삭제 성공 | `{ "data": {...} }` |
| **200** | `respondSuccessWithMeta($data, $meta)` | 목록 조회 + 페이지네이션 | `{ "data": [], "meta": {...} }` |
| **201** | `respondCreated($data)` | 리소스 신규 생성 | `{ "data": {...} }` |

### 4xx 클라이언트 에러

| Status | Error Code | 메서드 | 용도 | 사용 시점 |
|--------|------------|--------|------|-----------|
| **400** | `INVALID_INPUT` | `respondValidationError($msg, $details)` | 입력값 검증 실패 | 필수값 누락, 포맷 불일치, 비즈니스 규칙 위반 |
| **401** | `UNAUTHORIZED` | `respondUnauthorized($msg)` | 인증 실패 | 로그인 필요, 토큰 만료/불일치, 비밀번호 오류 |
| **403** | `FORBIDDEN` | `respondError('FORBIDDEN', $msg, 403)` | 인가 거부 | 권한 없음, 계정 비활성화, CSRF 토큰 검증 실패 |
| **404** | `NOT_FOUND` | `respondNotFound($msg)` | 리소스 없음 | DB 조회 결과 없음, 존재하지 않는 엔드포인트 |
| **405** | `METHOD_NOT_ALLOWED` | (Filter 전용) | HTTP 메서드 불허 | GET/POST/PUT/DELETE/OPTIONS 외 요청 |
| **409** | `CONFLICT` | `respondError('CONFLICT', $msg, 409)` | 리소스 충돌 | 중복 등록, 이미 처리됨, 상태 충돌 |
| **429** | `TOO_MANY_REQUESTS` | (Filter 전용) | 요청 한도 초과 | Rate limit 초과 |

### 5xx 서버 에러

| Status | Error Code | 메서드 | 용도 | 사용 시점 |
|--------|------------|--------|------|-----------|
| **500** | `INTERNAL` | `respondServerError($msg)` | 서버 내부 오류 | DB 실패, 외부 API 실패, 예외 catch |

## 3. Error Code 규칙

| 규칙 | 예시 | 위반 예시 |
|------|------|-----------|
| 현상 서술형 | `INVALID_INPUT` | ~~`VALIDATION_ERROR`~~ |
| suffix 없음 | `NOT_FOUND` | ~~`NOT_FOUND_ERROR`~~ |
| UPPER_SNAKE_CASE | `TOO_MANY_REQUESTS` | ~~`tooManyRequests`~~ |

**허용 Error Code 전체 목록:**

| Error Code | HTTP Status |
|------------|-------------|
| `INVALID_INPUT` | 400 |
| `UNAUTHORIZED` | 401 |
| `FORBIDDEN` | 403 |
| `CSRF_VALIDATION_FAILED` | 403 |
| `CSRF_TOKEN_EXPIRED` | 403 |
| `NOT_FOUND` | 404 |
| `METHOD_NOT_ALLOWED` | 405 |
| `CONFLICT` | 409 |
| `TOO_MANY_REQUESTS` | 429 |
| `INTERNAL` | 500 |

> 위 목록에 없는 Error Code(VALIDATION_FAILED, SERVER_ERROR, RESOURCE_NOT_FOUND 등)는 **구 코드**이며 사용 금지.

## 4. 판단 기준 가이드

### "이 에러는 몇 번을 써야 하나?"

```
클라이언트가 요청을 잘못 보냈는가?
├─ YES → 어떤 종류의 잘못인가?
│   ├─ 필수값 누락 / 포맷 오류 / 비즈니스 규칙 위반 → 400 INVALID_INPUT
│   ├─ 로그인 안 함 / 토큰 만료 → 401 UNAUTHORIZED
│   ├─ 로그인은 했지만 권한 없음 → 403 FORBIDDEN
│   ├─ 요청한 리소스가 존재하지 않음 → 404 NOT_FOUND
│   ├─ 이미 처리됨 / 중복 → 409 CONFLICT
│   └─ 요청 너무 많음 → 429 TOO_MANY_REQUESTS
│
└─ NO → 서버 측 문제인가?
    ├─ YES → 500 INTERNAL
    └─ NO → 200 OK (성공)
```

### 흔한 실수

| 상황 | 잘못된 코드 | 올바른 코드 | 이유 |
|------|------------|-------------|------|
| 로그인이 필요한 API에 비로그인 접근 | 500 | **401** | 인증 실패는 서버 에러가 아님 |
| DB에서 데이터 조회 결과 없음 | 500 | **404** | 리소스 미존재는 서버 에러가 아님 |
| 이미 신고된 댓글을 재신고 | 500 | **409** | 중복 요청은 상태 충돌 |
| 입력값 최소 길이 미달 | 500 | **400** | 검증 실패는 클라이언트 에러 |
| 짧은 시간 내 댓글 연속 등록 | 500 | **429** | rate limit 성격 |
| 비활성화된 계정으로 접근 | 401 | **403** | 인증은 됐으나 인가가 거부됨 |

## 5. 사용 예시 (Controller 코드)

### 200 OK — 조회 성공

```php
public function getProfile(): object
{
    $profile = $this->memberService->getProfile($this->member['ac_id']);
    return $this->respondSuccess($profile);
}
```

### 200 OK — 목록 + 페이지네이션

```php
public function getList(): object
{
    $result = $this->goodsRepository->getList($params);
    return $this->respondSuccessWithMeta($result['data'], [
        'currentPage' => $result['currentPage'],
        'perPage'     => $result['perPage'],
        'total'       => $result['total'],
        'lastPage'    => $result['lastPage'],
    ]);
}
```

### 201 Created — 리소스 생성

```php
public function register(): object
{
    $member = $this->authService->register($input);
    return $this->respondCreated($member);
}
```

### 400 INVALID_INPUT — 입력값 검증 실패

```php
// 단순 메시지
return $this->respondValidationError(lang('Error.member.ac_id.required'));

// 필드별 상세
return $this->respondValidationError(
    lang('Error.invalidInput'),
    ['ac_id' => lang('Error.member.ac_id.valid_email')]
);
```

### 401 UNAUTHORIZED — 인증 실패

```php
if (!$this->is_login) {
    return $this->respondUnauthorized(lang('Error.need_login'));
}
```

### 403 FORBIDDEN — 인가 거부

```php
if ($member['status'] === 'inactive') {
    return $this->respondError('FORBIDDEN', lang('Error.member.inactive_account'), 403);
}
```

### 404 NOT_FOUND — 리소스 없음

```php
$item = $this->itemsRepository->findByCode($code);
if (!$item) {
    return $this->respondNotFound(lang('Error.items.empty'));
}
```

### 409 CONFLICT — 중복/충돌

```php
if ($this->memberRepository->existsByPhone($phone)) {
    return $this->respondError('CONFLICT', lang('Error.member.phone_already_exists'), 409);
}
```

### 500 INTERNAL — 서버 에러

```php
try {
    $this->paymentService->process($order);
} catch (\Exception $e) {
    log_message('error', $e->getMessage());
    return $this->respondServerError(lang('Error.internal'));
}
```

## 6. 메시지 작성 규칙

| 규칙 | 좋은 예 | 나쁜 예 |
|------|---------|---------|
| `lang()` 함수 사용 필수 | `lang('Error.items.empty')` | `'상품이 없습니다.'` |
| lang key는 `Error.{domain}.{상황}` | `Error.call.history_empty` | `Error.network_error3` |
| 성공 메시지는 `Message.{domain}.{상황}` | `Message.goods.deleted` | `'商品が削除されました。'` |
| 하드코딩 일본어/한국어 금지 | `lang('Error.reject.already_blocked')` | `'既にブロックされた会員です。'` |
| 넘버링 금지 | `Error.chat.process_failed` | `Error.network_error2` |

### lang key 네이밍 패턴

```
Error.{모듈}.{상황}

예시:
Error.call.history_empty        — 통화 이력 없음
Error.goods.not_found           — 상품 조회 실패
Error.member.phone_already_exists — 전화번호 중복
Error.reject.already_blocked    — 이미 차단된 회원
Error.chat.inquiry_create_failed — 문의 생성 실패

Message.goods.deleted           — 상품 삭제 완료
Message.reject.block_completed  — 차단 완료
```

## 7. Filter 응답 포맷

Filter에서는 BaseApiController 메서드를 사용할 수 없으므로 직접 JSON을 설정한다.
**표준 포맷을 준수**할 것.

```php
// O 올바른 포맷
$response->setJSON([
    'error' => [
        'code'    => 'UNAUTHORIZED',
        'message' => '인증이 필요합니다.',
    ],
]);

// X 잘못된 포맷 (status 필드 혼입)
$response->setJSON([
    'status' => 'error',        // <- 이 필드 금지
    'error'  => [
        'code'    => '...',
        'message' => '...',
    ],
]);
```

### Filter별 응답 헤더

| Filter | 필수 헤더 |
|--------|-----------|
| AllowedMethodsFilter (405) | `Allow: GET, POST, PUT, DELETE, OPTIONS` |
| RateLimitFilter (429) | `Retry-After: {seconds}` |

## 8. 구 코드 → 표준 코드 매핑 (마이그레이션 참조)

| 구 Error Code | 표준 Error Code | 구 메서드 | 표준 메서드 |
|---------------|----------------|-----------|-------------|
| `VALIDATION_FAILED` | `INVALID_INPUT` | — | `respondValidationError()` |
| `SERVER_ERROR` | `INTERNAL` | — | `respondServerError()` |
| `RESOURCE_NOT_FOUND` | `NOT_FOUND` | — | `respondNotFound()` |
| (레거시 body) | (표준 body) | `responseJsonStatus(200, ...)` | `respondError(...)` |
| (레거시 body) | (표준 body) | `setErrorResponse(...)` | `respondError(...)` |
