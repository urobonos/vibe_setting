여러 이슈를 **가로질러 배치**하는 층이다. 루프 자체는 만들지 않는다 — 트랙마다 `/taskflow:code` 를 그대로 부르고, 이 커맨드는 **무엇을 어느 트랙에 넣을지 · 어떤 순서로 정착할지**만 정한다.

## 무엇을 하지 않는가

**리뷰·게이트·캡을 재정의하지 않는다.** 트랙 하나의 안쪽은 `/taskflow:code` 와 완전히 동일하다 (범위 확인 → worktree → 개발 → 리뷰 2인 루프 5회 → 적대적 검증 2회 → 보고). 그 계약을 여기서 다시 쓰지 않는다.

**그룹핑을 기계가 결정하지 않는다.** 파일 축 연결요소까지는 명령으로 뽑지만, **같은 메서드인가**는 소스를 읽어야 알고 그건 본체 판단이다 (§"합침 판정").

**정착하지 않는다.** worktree 와 커밋만 남기고, 정착은 `/taskflow:code` 와 같이 사용자 승인 흐름을 탄다.

## 흐름

```
1. 목록      : range → 이슈 집합. 남의 세션 점유분 자동 제외
2. 파일 축   : 각 이슈의 `관련 파일` → 연결요소(그룹) 계산
3. 합침 판정 : 같은 파일 안에서 같은 메서드를 고치는 쌍을 본체가 소스로 확인 → 트랙 합침 (필수)
4. 배치      : 트랙 표를 사용자에게 1회 제시 → 승인
5. 실행      : 슬롯 상한만큼 병렬로 /taskflow:code. 나머지는 대기열
6. 정착      : 순서대로. 앞이 정착하면 뒤는 rebase + 재현물 재실행 후에만 정착
```

## 1단계 — 목록과 제외

```bash
# 도메인 축
awk -F'\t' '$2=="Member"{print $1}' docs/wbs/tools/iss-domain-map.tsv
# 번호 범위 축은 파일명 glob 으로
```

**남의 세션이 잡은 것은 뺀다.** 두 축으로 본다 — `git worktree list` 에 그 슬러그가 있는가, 최근 커밋(`git log --since` 3일)이 **코드 파일을 건드리면서** 그 번호를 언급하는가.

**문서 커밋은 점유가 아니다.** 등재(`docs(issue): ISS-NNN 등재`)·조치 절 갱신·상태 전이는 "누가 이 번호를 적었다" 는 뜻이지 "코드를 잡고 있다" 가 아니다. 이걸 점유로 세면 **등재된 거의 전부가 제외되어 트랙이 빈다**(2026-09-15 실측 — Member 잔여 14건 중 5건이 등재 커밋만으로 걸렸다). `git log --name-only` 로 그 커밋이 만진 파일을 보고 코드 파일(php/js/ts/py/sql)이 있을 때만 제외한다.

**형제째 뺀다.** 제외된 이슈와 같은 메서드를 고치는 이슈가 있으면 그것도 뺀다 — 한쪽만 잡으면 나중 정착이 남의 설계를 되돌린다.

## 2단계 — 파일 축 연결요소

각 이슈 frontmatter 의 `관련 파일` 을 뽑아 **한 파일이라도 공유하면 같은 그룹**으로 묶는다.

```bash
sed -n '/^관련 파일:/,/^---/p' "$f" | grep '^  - '
```

**`관련 파일` 은 증상 위치라 조치 대상과 다를 수 있다.** 이슈 §4 에 조치 파일이 적혀 있으면 그쪽이 우선이다 — 조치가 미채택이면 증상 위치로 근사하고, 그 근사치임을 표에 밝힌다.

## 3단계 — 합침 판정 (기계가 못 한다)

**같은 파일을 공유하는 이슈 쌍마다 "같은 메서드를 고치는가" 를 소스로 확인한다.**

| 판정 | 처리 |
|---|---|
| 다른 메서드 | 별도 트랙. rebase 가 깨끗하다 |
| **같은 메서드** | **한 트랙으로 합친다.** 따로 띄우면 나중 정착이 앞의 설계를 되돌린다 |

실측 사례 — `ISS-311`(3계 쓰기를 트랜잭션으로 안 묶는다)과 `ISS-778`(트랜잭션 밖에서 외부 API 를 부른다)은 둘 다 `CoinModel::insertCoin()` 의 **경계 설계**를 바꾼다. 따로 고치면 두 번째가 첫 번째 경계를 다시 짠다.

**이 판정을 건너뛰고 배치하지 않는다.** 확인이 안 되면 그 쌍은 합쳐서 한 트랙에 넣는다 (fail-safe — 합치면 느려질 뿐이고, 가르면 되돌린다).

## 4단계 — 배치 표

사용자에게 1회 제시하고 승인받는다. 이후 트랙 구성은 바꾸지 않는다.

```
| 트랙 | 이슈 | 묶는 파일 | 합침 사유 | 진입 단계 |
```

**진입 단계를 반드시 적는다 — 전부 `/taskflow:code` 로 가지 않는다.** 이슈 §4 조치 절이 `미채택`·`판단 대기` 면 **성공 기준이 없어서** 코드 루프에 넣을 수 없다. 리뷰어는 대조 기준이 없으면 계약대로 `[High] 판정 불가` 로 되돌린다(fail-closed).

| 이슈 §4 상태 | 진입 |
|---|---|
| 계획 문서 `Plan Complete` | `/taskflow:code` 또는 `/taskflow:tick` |
| 조치 채택, 계획 없음 | `/taskflow:plan` 먼저 |
| **`미채택`·`판단 대기`·판정 불명** | **`/taskflow:analyze` 먼저.** 조치안 선택이 사용자 결정이면 거기서 멈춘다 |

한 트랙 안에서 단계가 갈리면(허브는 계획 완료, 나머지는 미채택) 허브만 코드로 보내고 나머지는 분석 트랙으로 따로 센다. **분석 트랙은 리뷰어를 안 쓰므로 슬롯 회계가 다르다** — 코드 트랙 1개와 분석 트랙 1개는 슬롯 2~3을 쓴다.

**슬롯 회계를 표 아래 1줄로 적는다.** 동시 Agent 상한이 N이면 개발 트랙은 최대 N−2 다 — 리뷰어 2인이 그 안에서 돌기 때문이다. 상한 3이면 **동시 개발 1트랙 + 리뷰 2인**, 또는 개발 2트랙을 띄우고 리뷰를 순차로 돌린다. **개발 3트랙은 리뷰어를 못 띄워서 루프가 멈춘다.**

## 5단계 — 실행

트랙마다 `/taskflow:code` 를 부른다. 인자는 그 이슈의 성공 기준·테스트 범위·비목표·worktree 경로다 (`/taskflow:code` §"대조 기준" 그대로).

**캡은 트랙별로 독립이다.** 공유하면 앞 트랙이 5라운드를 다 먹고 뒤 트랙이 검증 없이 끝난다.

**worktree 는 이슈마다 따로 판다.** 하나에 몰면 diff 가 섞여 개별 리뷰가 불가능해진다 — 리뷰어는 "이 변경" 을 판정하는데 그 경계가 없어진다.

## 교차 발견 — 한 트랙의 게이트가 다른 축을 깰 때

적대적 검증이 **그 트랙에서 고칠 수 없는 원인**을 찾는 경우가 있다. 실측 사례 — `ISS-200`(엑셀 view)의 게이트 2회차가 깬 것은 view 가 아니라 공용 헬퍼 `mask_name()` 이었다.

| 순서 | 처리 |
|---|---|
| 1 | 발견한 트랙은 **`BROKEN` 인 채로 멈춘다.** 자기 범위 밖을 고치지 않는다 |
| 2 | 원인 축을 **새 이슈로 등재**한다 (채번 4축 실측 = `issue/README` 대역 표) |
| 3 | 그 이슈를 새 트랙으로 앞세운다 |
| 4 | 정착 후 원 트랙을 rebase → **재현물 재실행** → 재개 |

**2를 건너뛰면 그 발견이 응답 텍스트로만 남고 세션과 함께 사라진다.** 레포 규약이 "대화에만 있는 이슈는 없는 이슈다" 인 이유가 이것이다.

## 6단계 — 정착 순서와 재검증

**앞 트랙이 정착하면 뒤 트랙의 통과는 낡는다.** 통과 시점의 develop 이 아니기 때문이다.

- rebase 한 트랙은 **게이트 재현물을 재실행하기 전에는 정착하지 않는다**
- 재현물이 없으면(UPHELD 로 끝난 트랙) 그 트랙의 BASELINE 을 재실행한다
- 수치가 달라지면 정착을 멈추고 보고한다

허브가 있는 그룹은 **허브를 먼저 정착**한다. 허브가 계약(반환 컬럼·응답 키·시그니처)을 정하면 나머지가 그 위에서 갈리지 않는다.

## SSOT — 여기서 재정의하지 않는다

| 조각 | SSOT |
|------|------|
| 트랙 하나의 루프 전체 (리뷰 2인·캡 5·게이트 2·반박 판정·잔여 처리) | `custom-plugin/taskflow/commands/code.md` |
| 리뷰어 spawn 규약 | `custom-plugin/taskflow/commands/watch.md` §"코드 축" |
| 적대적 검증 계약 | `custom-plugin/taskflow/agents/adversary.md` |
| worktree 생성·정착 | `custom-plugin/git/commands/{create,merge}.md` |
| 이슈 채번·상태 전이·C1~C3 | 레포 `docs/wbs/issue/README.md` |
| 동시 Agent 상한 | 세션 메모리 / 사용자 지시 |

## 호출 예

```
/taskflow:range domain=Member pending
  → 14건 → 파일 축 6그룹 → 합침 판정 2쌍 → 트랙 4개 배치 표 제시

/taskflow:range ISS-850..ISS-855
  → 번호 범위. 남의 세션 점유분은 표에 표시만 하고 트랙에서 제외

/taskflow:range domain=Member High
  → 심각도 필터. 잔여 High 만
```

## §3 Checkpoint 우선 적용

- 배치 표 승인은 **1회**다. 승인 후 트랙 구성을 바꾸려면 다시 올린다
- 정착·머지·push 는 `/taskflow:code` 와 동일하게 §3 을 탄다. 이 커맨드가 우회 통로가 되지 않는다
- 트랙이 §3 매칭(비가역·외부 시스템·3파일+ 아키텍처)에 걸리면 그 트랙만 멈추고 보고한다. 나머지 트랙은 계속 돈다

## 이 커맨드가 줄이는 것은 시간이 아니다

수정을 병렬로 당겨도 리뷰가 트랙당 2인이라 결국 순차로 돈다. 루프 비용의 대부분이 리뷰라서 전체 시간은 생각만큼 줄지 않는다.

**값은 배치 실수를 막는 데 있다** — 같은 메서드를 따로 띄우는 것, 남의 세션 파일에 들어가는 것, 정착 후 재검증을 빠뜨리는 것, 교차 발견을 등재 없이 흘리는 것. 넷 다 이 레포에서 실제로 났던 사고다.
