# 보안 그룹

## Lambda VPC 설정

Lambda 가 Aurora 에 접근하려면 **VPC 내에 배치**해야 한다.

| 설정 | 권장값 | Why (사유) |
|------|--------|-----------|
| **서브넷** | 프라이빗 서브넷 2개 이상 (Multi-AZ) | 단일 AZ 장애 시 다른 AZ 로 페일오버 가능 |
| **보안 그룹** | Lambda 전용 보안 그룹 생성 | 다른 서비스 SG 에 Lambda 규칙이 섞이면 권한 분리 무력화 |
| **NAT Gateway** | Lambda 가 외부 API 호출 필요 시 NAT Gateway 필수 | 프라이빗 서브넷의 Lambda 는 인터넷 직접 접근 불가 — NAT 경유 필요 |

## 보안 그룹 규칙

### Lambda 보안 그룹 (sg-lambda)

| 방향 | 프로토콜 | 포트 | 대상 | 사유 |
|------|----------|------|------|------|
| **Outbound** | TCP | 3306 | sg-aurora | Aurora 연결 |
| **Outbound** | TCP | 443 | 0.0.0.0/0 | AWS API 호출 (SQS, SNS 등) |

### Aurora 보안 그룹 (sg-aurora)

| 방향 | 프로토콜 | 포트 | 대상 | 사유 |
|------|----------|------|------|------|
| **Inbound** | TCP | 3306 | sg-lambda | Lambda 에서 DB 접근 허용 |
| **Inbound** | TCP | 3306 | sg-ec2 | EC2(CI4 서버)에서 DB 접근 허용 |

### EC2 보안 그룹 (sg-ec2)

| 방향 | 프로토콜 | 포트 | 대상 | 사유 |
|------|----------|------|------|------|
| **Inbound** | TCP | 443 | ALB 보안 그룹 또는 0.0.0.0/0 | HTTPS 트래픽 |
| **Inbound** | TCP | 22 | 관리자 IP 만 | SSH (특정 IP 제한 필수) |
| **Outbound** | TCP | 3306 | sg-aurora | Aurora 연결 |
| **Outbound** | TCP | 443 | 0.0.0.0/0 | 외부 API, AWS API 호출 |

## 보안 그룹 규칙

| 규칙 | 설명 / Why |
|------|-----------|
| **0.0.0.0/0 Inbound 최소화** | SSH 는 관리자 IP 만, HTTP/HTTPS 는 ALB 경유. **Why:** 인터넷 전체 개방은 봇넷 스캔/brute-force 공격 표적 |
| **보안 그룹 간 참조** | IP 대신 보안 그룹 ID 로 참조 (sg-xxx). **Why:** IP 변경(인스턴스 교체/재시작 시 IP 변동) 에 안전 — SG ID 는 리소스 생애주기 동안 불변 |
| **포트 범위 제한** | `0-65535` 같은 범위 대신 필요한 포트만 명시적으로 개방한다. **Why:** 광범위 개방 시 미사용 포트로 들어오는 비정상 트래픽 차단 불가 |
| **변경 시 Checkpoint** | 보안 그룹 규칙 추가/수정/삭제 시 반드시 사용자 승인. **Why:** 잘못된 SG 변경은 운영 트래픽 즉시 차단 가능 — 비가역적 영향 위험 |
