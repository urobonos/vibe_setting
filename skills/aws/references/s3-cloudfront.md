# S3 / CloudFront 스토리지 정책

| 항목 | 설정 | Why (사유) |
|------|------|-----------|
| **S3 버킷** | 국가별 분리 또는 prefix 분리 (`us/`, `kr/`, `jp/`) | 국가별 데이터 주권 요구 + 리전별 레이턴시 최적화 |
| **CloudFront** | S3 Origin Access Control(OAC) 로 직접 접근 차단 | S3 직접 접근 허용 시 CloudFront 우회 가능 — WAF/캐시 정책 무력화 |
| **CRR (Cross-Region Replication)** | 글로벌 확장 시 리전 간 복제 검토 (비용 대비 레이턴시 이점 평가) | 사용자 가까운 리전에서 읽기 — 다만 복제 비용/지연 트레이드오프 존재 |
| **버저닝** | 프로덕션 버킷 버저닝 활성화 | 실수 삭제/덮어쓰기 복원 가능 — 미설정 시 비가역적 손실 |
| **수명 주기** | 비활성 객체 90일 후 Glacier 전환 검토 | 콜드 데이터 비용 절감 (Standard → Glacier 약 80% 절감) |

- S3 퍼블릭 접근 차단 (Block Public Access 활성화). **Why:** 실수 공개 정책 적용 방지 — 계정 레벨 차단이 정책 레벨 실수보다 우선 적용
- CloudFront 캐시 무효화는 배포 스크립트에 포함. **Why:** 정적 파일 갱신 후 CDN 캐시가 구버전 서빙 — 사용자에게 변경 미반영
